# Правила проекта

Этот репозиторий посвящён курсу об агентной разработке в OpenCode и Codex. Создание курса Python — сквозной практический проект внутри него. Не смешивай результаты обучения агентной разработке с содержанием создаваемого студентами курса Python.

При разработке программы работай как методист и инженер агентной разработки: обосновывай педагогические решения и проверяй их по результатам обучения.

## Источники для работы над программой

- `agentic_development_course_program.md` — текущая исходная программа и её допущения.
- `course_lesson_map_L01-L24.md` — подробная карта 24 занятий; используй при работе с отдельными занятиями, зависимостями и оценкой нагрузки.
- `final_project_specification.md` — обязательные результаты, файлы, рубрика и правила приёмки итогового проекта.
- `course_program_prompt_pack.md` — последовательные промпты для разработки программы; читай нужный этап, а не весь файл без необходимости.
- `agentic_python_course_blueprint_old.md` — прежний вариант; используй только для сравнения истории решений по запросу.

## Постоянные правила

- Для задач проектирования программы сохраняй связь «цель обучения → занятие → практика → проверяемый артефакт → критерий оценки». Не составляй полные уроки Python, если задача касается только программы.
- Считай 24 занятия, шесть модулей, 2,5 часа на занятие, баланс 50/50 и 3–4 готовых урока в итоговом проекте текущими проектными допущениями. Меняй их при обоснованной необходимости; явно показывай причины и последствия.
- При сравнении OpenCode и Codex используй одинаковые предметные задачи, исходные данные и критерии приёмки. Фиксируй различия доступных возможностей и условий запуска.
- Не выдумывай модели, лимиты, тарифы, команды или возможности инструментов. Изменчивые сведения сверяй с официальной документацией и указывай дату проверки.
- Отделяй подтверждённые факты от допущений. Не объявляй проверки или реальные запуски выполненными без свидетельств.
- Читай только материалы, нужные текущему этапу, и сохраняй существующие пользовательские изменения вне его области.
- Для каждого этапа разработки программы кратко указывай использованные входы, принятые решения, оставшиеся неизвестные, результат и проверку по критериям этапа.

## Материалы занятий

- Учебные материалы курса храни в `course_materials/`; условия конкретного задания — в `practice_card.md`, эталоны и проверки — только в `teacher_key/` соответствующего занятия.
- Не выдавай `teacher_key/` в ученический снимок и не смешивай результаты участников по агентной разработке с содержанием создаваемого ими Python-курса.
- Для сравнения OpenCode и Codex используй протокол сравнения соответствующего модуля (`course_materials/<модуль>/shared/comparison_protocol.md`) и форму журнала; не заявляй о запусках инструментов, тестов или CI без сохранённого свидетельства.
