# Журнал запуска и сравнения

Заполняется на каждое занятие L01–L04. Один журнал — один участник (или пара) и один учебный эпизод. Если попытка повторяется, добавляется новый номер попытки с причиной повтора; старый результат не удаляется.

> Не записывайте то, чего не видите. Если версия, модель, расход или время недоступны, пишите **«недоступно»**. Пустая ячейка хуже честной пометки: она выглядит как отсутствие различия.

## 4. Дополнения по занятиям

### L01. Среда, полномочия, Git

- Дерево файлов в каждой копии: `tree` или список.
- Коммит: хеш, сообщение, `git status --porcelain`.
- События разрешений: сколько запросов, что разрешено, что отклонено.
- Проверка отсутствия изменений вне области: как проверяли, что увидели.
- Выбранная первичная копия и почему она назначена заранее.

### L02. Минимальный Python

- Два входа и два фактических вывода.
- Код возврата `run_greeting.py`.
- Один дополнительный вход для устной проверки: что вернула функция.
- Где участник увидел ошибку и как её прочитал.

### L03. Тест и исправление

- Три поведения и три теста: соответствие один к одному.
- Красный запуск: команда, вывод, какой тест упал.
- Зелёный запуск: команда, вывод.
- Diff исправления: какие строки изменены.
- Проверка на baseline: тесты падают на исходном дефектном файле.

### L04. Первое сравнение

- Базовая ветка и коммит.
- Две ветки и две рабочие копии.
- Старые тесты: результат в каждой среде.
- Новые тесты: результат в каждой среде.
- Файлы, изменённые сверх разрешённых.
- Оценка по рубрике: четыре направления, 0–3.
- Выбранная ветка и команда, которой выбор внесён в основную линию.

## 5. Приложения

- Полный вывод команд: путь к файлу или вставка.
- Полный diff: путь к файлу или вставка.
- Скриншоты и логи: только если они не заменяют текст запроса, diff и проверки.
- Секреты, токены и личные данные не сохраняются.
