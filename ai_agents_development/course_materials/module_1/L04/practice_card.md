# L04. Практика: первое сравнение

**Аудитория:** участники после L03  
**Предпосылки:** L01 — Git; L02 — запуск; L03 — тесты и исправление  
**Время:** 75 минут  
**Цель:** добавить один необязательный параметр в двух средах, сравнить попытки по одной рубрике и выбрать проверенный вариант  
**Артефакт:** две ветки от одного коммита, таблица критериев, выбор  
**Оценивание:** [`../shared/practice_rubric.md`](../shared/practice_rubric.md), [`../assessment.md`](../assessment.md)

## Входы и снимок

Преподаватель выдаёт базовый репозиторий `L04-base/` с коммитом `L04: base`:

```text
L04-base/
  greet.py              рабочая версия после L03
  tests/test_greet.py   три старые теста
  task_card.md          условие нового параметра
```

Если базового репозитория нет, создайте его из [`snapshot/`](snapshot/):

```bash
mkdir -p L04-base/tests
cp snapshot/greet.py snapshot/task_card.md L04-base/
cp snapshot/tests/test_greet.py L04-base/tests/
cd L04-base
git init -b main
git add greet.py tests/test_greet.py task_card.md
git commit -m "L04: base"
```

Если установленный Git не поддерживает `git init -b`, выполните `git init` и затем `git branch -M main`. Команды `git worktree` требуют поддержки worktree в установленном Git; преподаватель проверяет это до занятия.

## Ограничения

- Менять только `greet.py` и `tests/test_greet.py`.
- Не менять три существующих теста.
- Не добавлять зависимости.
- Не менять базовый коммит и основную ветку во время попыток.
- Запрос в обеих средах — дословно одинаковый.
- Каждая попытка — новый сеанс и отдельная рабочая копия.

## Одинаковое задание для OpenCode и Codex

### Шаг 1. Две рабочие копии — 10 минут

В `L04-base/`:

```bash
git status
git log --oneline -1
git worktree add ../L04-opencode -b attempt/opencode
git worktree add ../L04-codex -b attempt/codex
git worktree list
```

Проверьте в каждой копии:

```bash
git rev-parse HEAD
```

Значения должны совпадать. Запишите базовый коммит, порядок попыток и первичную среду.

Если преподаватель уже создал копии, не повторяйте команды; проверьте `git worktree list` и `git rev-parse HEAD`.

### Шаг 2. Попытка 1 — 20 минут

В `L04-opencode/` или `L04-codex/` (по назначенному порядку) откройте новый сеанс. Запрос:

```text
В этой рабочей копии есть greet.py и tests/test_greet.py.
Добавь функции greet необязательный параметр greeting со значением по умолчанию "Привет".
Сохрани все текущие поведения:
- greet("Ada") -> "Привет, Ada!"
- greet("  Ada  ") -> "Привет, Ada!"
- greet("Ada Lovelace") -> "Привет, Ada Lovelace!"

Добавь в tests/test_greet.py ровно два новых теста:
- greet("Ada", "Здравствуйте") -> "Здравствуйте, Ada!"
- greet("  Ada  ", "Здравствуйте") -> "Здравствуйте, Ada!"

Не меняй существующие три теста. Меняй только greet.py и tests/test_greet.py.
Запусти python3 -m unittest discover -s tests -v и покажи полный вывод и git diff.
```

После запуска:

```bash
python3 -m unittest discover -s tests -v
git diff
git add greet.py tests/test_greet.py
git commit -m "L04: add greeting parameter (opencode)"
```

Если выбрана другая среда, измените только подпись в сообщении коммита.

### Шаг 3. Попытка 2 — 20 минут

Повторите тот же запрос во второй рабочей копии, в новом сеансе. Коммит:

```bash
git add greet.py tests/test_greet.py
git commit -m "L04: add greeting parameter (codex)"
```

### Шаг 4. Сравнение — 15 минут

Заполните таблицу. Для A–C оцените каждую попытку по 0–3; для D — итоговое сравнение.

| Направление | OpenCode | Codex | Доказательство |
|---|---:|---:|---|
| A. Границы и безопасность | | | |
| B. Результат и техническая корректность | | | |
| C. Проверка и свидетельства | | | |
| D. Сравнение и обоснование (одна оценка на обе попытки) | | — | |

Факты для таблицы:

- старые три теста проходят;
- новые два теста проходят;
- изменены только `greet.py` и `tests/test_greet.py`;
- существующие тесты не изменены;
- diff понятен;
- ручные правки записаны.

### Шаг 5. Выбор и слияние — 5 минут

Выберите ветку по фактам и запишите обоснование. Затем в `L04-base/`:

```bash
git merge --ff-only attempt/opencode
```

Замените имя ветки на выбранную. Если слияние не проходит без конфликта, остановитесь, запишите причину и обратитесь к преподавателю. Не используйте `--force`.

После слияния:

```bash
python3 -m unittest discover -s tests -v
git log --oneline -3
```

### Шаг 6. Журнал и сдача — 5 минут

Заполните раздел L04 формы [`../shared/run_journal.md`](../shared/run_journal.md):

- базовый коммит и две ветки;
- порядок и первичная среда;
- запрос;
- результаты тестов;
- diff и ручные правки;
- таблица 0–3;
- выбранная ветка и команда слияния;
- предел вывода.

## Ожидаемое поведение

- Старые вызовы без второго аргумента работают как раньше.
- Новый аргумент подставляется в приветствие.
- Пробелы по краям имени по-прежнему удаляются и с новым приветствием.
- Обе ветки начинаются от одного коммита.
- Если агент меняет существующий тест, вы возвращаете тест и записываете отклонение.

## Формат сдачи

```text
<папка участника>/
  L04-base/
    .git/
    greet.py
    tests/test_greet.py
    task_card.md
  L04-opencode/
  L04-codex/
  journal-L04.md
```

В `L04-base/` видна выбранная ветка после слияния. Журнал лежит вне репозитория.

## Критерии приёмки

| Критерий | Принято |
|---|---|
| База | Обе попытки от одного коммита; порядок записан |
| Старые тесты | Три исходных теста не изменены и проходят |
| Новые тесты | Два новых теста проходят |
| Поведение | Старые вызовы и два новых случая совпадают |
| Границы | Изменены только `greet.py` и `tests/test_greet.py` |
| Сравнение | Таблица 0–3, факты, выбор, предел вывода |
| Слияние | Выбранная ветка внесена без `--force`; тесты повторены |

## Если что-то пошло не так

- **`HEAD` не совпадает** — ветки созданы не от одного коммита; пересоздайте.
- **`worktree already exists`** — используйте выданные копии; не удаляйте чужие worktree.
- **Старый тест изменён** — верните его, добавьте новый.
- **Слияние не fast-forward** — остановитесь, запишите, позовите преподавателя.
- **Одна среда недоступна** — запишите ошибку; выполните доступную попытку, не выдумывайте вторую.
- **Обе попытки одинаковы** — это нормально; выбор всё равно обосновывается проверками и удобством повторения.
