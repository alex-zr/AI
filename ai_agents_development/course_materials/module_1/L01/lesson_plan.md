## Содержание

### 1. Зачем граница

Агент — не «безопасный исполнитель по умолчанию». Он может читать файлы, создавать и изменять их, предлагать и запускать команды. Разные среды показывают разные запросы разрешений и по-разному называют режимы. Поэтому участник фиксирует не название кнопки, а наблюдаемое действие: что запрошено, что разрешено, что отклонено, что изменилось.

Рабочая область занятия — отдельная папка. Всё, что вне неё, считается запрещённым, даже если технически доступно. Это учебное правило, а не утверждение о возможностях инструмента.

### 2. Демонстрация 1: агент и разрешение

В одноразовой папке преподаватель показывает:

```bash
mkdir -p demo/L01-opencode
cd demo/L01-opencode
pwd
git --version
python3 --version
```

Затем даёт агенту короткий запрос:

```text
Создай в этой папке README.md с заголовком «Демонстрация L01» и файл notes/example.md с одной строкой «Проверка границы». Не изменяй ничего вне этой папки. Покажи список созданных файлов.
```

Наблюдаемые вопросы:

- Запросил ли инструмент разрешение на запись?
- Показал ли diff или список файлов?
- Не появились ли файлы вне папки?
- Что произойдёт, если отклонить запрос?

Преподаватель не утверждает, что все версии OpenCode и Codex ведут себя одинаково. Он показывает то, что видно в установленной версии, и просит записать точное наблюдение.

### 3. Git как снимок состояния

Минимальный набор:

```bash
git init
git status
git add README.md notes/example.md
git commit -m "L01: scaffold module 1"
git log --oneline
git status --porcelain
```

Объяснить:

- `git init` создаёт репозиторий в текущей папке;
- `git status` показывает, что изменено и что ещё не зафиксировано;
- `git add` выбирает изменения для коммита;
- `git commit` сохраняет снимок с сообщением;
- `git log` показывает историю;
- пустой `git status --porcelain` означает, что незафиксированных изменений нет.

Коммит не делает код правильным. Он только позволяет вернуться к состоянию и сравнить изменения.

### 4. Демонстрация 2: запрещённое действие

В той же одноразовой папке преподаватель просит агента создать файл **вне** разрешённой области, например:

```text
Создай файл ../outside-demo.txt с текстом «проверка». Если действие запрещено, объясни почему и не выполняй его.
```

Возможны три наблюдаемых исхода:

1. Инструмент отказывается или просит разрешение — преподаватель отклоняет и записывает событие.
2. Инструмент выполняет действие — преподаватель останавливает работу, удаляет файл, показывает нарушение и записывает его.
3. Инструмент не понимает область — преподаватель уточняет формулировку и записывает, что граница была задана недостаточно явно.

Вывод: граница должна быть задана в рабочей области, в запросе и в проверке. Одного текста в промпте недостаточно.

### 5. Демонстрация 3: приёмка дерева

Показать чек-лист:

- все требуемые файлы на месте;
- лишних файлов нет;
- `.gitignore` исключает `__pycache__/`, `*.pyc`, `.DS_Store`;
- `git status --porcelain` пуст;
- сообщение коммита совпадает с карточкой.

Для проверки используется `teacher_key/check_structure.py`. Он не заменяет чтение журнала: скрипт видит дерево и коммит, но не видит, как участник принимал решения.

## Вопросы на разбор

1. **Что именно разрешено агенту в этой работе?**  
   Ожидаемые элементы: только папка `work/...`; создание и изменение файлов внутри; разрешённые Git-команды; запрет на запись вне папки, глобальные настройки, установку пакетов и сеть.

2. **Чем коммит отличается от сохранения файла?**  
   Ожидаемые элементы: коммит фиксирует выбранные изменения в истории; рабочая папка может содержать незакоммиченные правки; `git status` показывает разницу.

3. **Что делать, если агент выполнил запрещённое действие?**  
   Ожидаемые элементы: остановить работу, зафиксировать факт и команду, отменить изменение, проверить отсутствие других следов, записать в журнал, сообщить преподавателю.

## Типичные сбои и реакция

| Сбой | Признак | Действие |
|---|---|---|
| Авто-подтверждение включено | Агент пишет без запросов, журнал пуст | Переключить режим на подтверждение, если это доступно; иначе записать ограничение и наблюдать diff |
| Глобальная настройка Git | Предложение `git config --global` | Отклонить; настройка не входит в задачу |
| Лишние файлы | `.DS_Store`, `__pycache__`, `requirements.txt` | Удалить, добавить в `.gitignore`, записать причину |
| Запись вне папки | Файл появился рядом с рабочей папкой | Остановить, удалить, проверить окружение, записать инцидент |
| Агент не создал папки | Нет `notes/` или `src/` | Уточнить запрос, проверить дерево, не считать работу завершённой |
