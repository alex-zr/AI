## S02. Результаты, предпосылки, артефакт

К концу занятия вы умеете:

1. Создавать изолированную рабочую папку и называть разрешённые и запрещённые пути.
2. Фиксировать запрос разрешения или отказ и объяснять решение.
3. Создавать заданное дерево и первый коммит; проверять его через `git status` и `git log`.
4. Сравнивать две попытки по одинаковым полям журнала и не обобщать один запуск.

**Предпосылки:** нет. Python, Git и тесты не требуются.  
**Артефакт:** две рабочие копии, коммиты в обеих (первичная — для сдачи), журнал разрешений и сравнения.

## S03. Зачем это в сквозном проекте

Сегодняшний репозиторий — основа всего проекта:

```text

  → L02 функция greet и запуск
    → L03 тесты и исправление
      → L04 сравнение двух сред
        → … → L24 защита проекта
```

Без границы нельзя доказать, что изменение сделал агент, а не человек.  
Без коммита нельзя сравнить состояние «до» и «после».

`AGENTS.md` появится позже, на L11. Сегодня — только разовая задача и её границы.

## S04. Что агент умеет и что ему разрешено

В зависимости от настроек среды агент может:

- читать файлы;
- создавать и изменять файлы;
- предлагать и запускать команды.

Но **«умеет» не значит «разрешено»**. Разрешение задаёте вы: рабочей папкой, запросом, режимом подтверждений и проверкой.

| Наблюдение | Что записываем |
|---|---|
| Агент просит разрешение на запись | Что именно запрошено |
| Агент показывает список файлов или diff | Что изменилось |
| Агент предлагает команду | Разрешена ли она карточкой |
| Агент молча пишет файлы | Фактическое поведение и ограничение режима |

## S05. Рабочая область: где агенту можно работать

На занятии у вас **две отдельные папки**:

```text
<папка участника>/
  L01-opencode/     только эта папка разрешена агенту
  L01-codex/        только эта папка разрешена агенту
  journal-L01.md    журнал вне репозиториев
```

Всё, что выше или рядом, — **вне области**. Даже если технически доступно, по правилам занятия это запрещено.

Первичная среда назначена преподавателем **до старта**. После просмотра результатов её менять нельзя. Вторая среда всё равно выполняется и записывается.

Преподаватель может заранее положить контрольный файл рядом с папками. Если он изменился — граница нарушена.

## S06. Как принимать решение о разрешении

Пять шагов:

1. Прочитайте, что именно запрашивает инструмент.
2. Сверьте с разрешённой областью и списком действий.
3. Разрешено — разрешите и запишите.
4. Запрещено — отклоните и запишите причину.
5. Непонятно — отклоните и спросите преподавателя.

Не «пробуйте посмотреть, что будет». Не включайте авто-подтверждение, если доступен режим подтверждения.

---

## S07. Разрешено и запрещено

| Разрешено | Запрещено |
|---|---|
| Создавать и изменять файлы внутри своей папки | Писать, перемещать или удалять файлы вне папки |
| `git init`, `status`, `add`, `commit`, `log`, `diff` | `git config --global` |
| `python3 --version`, `git --version` | Установка пакетов и зависимости |
| Разрешать или отклонять запросы инструмента | Сетевые команды, скачивание, публикация |
| Записывать наблюдения в журнал | Секреты, токены, личные данные |

Если действие не описано в карточке — считайте его запрещённым до разрешения преподавателя.

## S10. Демонстрация 1: что записать

| Что наблюдали | Как записать |
|---|---|
| Запрос разрешения | Дословно: что запрошено |
| Ваше решение | «Разрешено» или «Отклонено» и почему |
| Изменения | Список файлов, `git status`, diff |
| Выход за область | Путь, время, что сделали |
| Разрешений не было | «Инструмент не запросил разрешение» + режим |

Не пишите «агент всё сделал правильно» без перечня файлов и проверки. Не обобщайте один показ на все версии и модели.

## S11. Git: снимок состояния

```text
Рабочая папка          Индекс              История
(ваши файлы)    →   (подготовлено)   →   (коммит)
```

- **Рабочая папка** — то, что вы видите и редактируете.
- **Индекс** — изменения, выбранные для следующего коммита.
- **Коммит** — сохранённый снимок с сообщением.

Коммит не делает код правильным. Он позволяет вернуться к состоянию и сравнить изменения.

## S12. Пять Git-команд занятия

| Команда | На какой вопрос отвечает |
|---|---|
| `git init` | Где начинается история этого репозитория? |
| `git status` | Что изменено и что ещё не зафиксировано? |
| `git add <файлы>` | Какие изменения войдут в коммит? |
| `git commit -m "<сообщение>"` | Как называется этот снимок? |
| `git log --oneline` | Какие снимки уже есть? |

Проверка чистоты:

```bash
git status --porcelain
```

Пустой вывод означает: незафиксированных изменений нет.

---

## S13. Коммит и сообщение

Для L01 сообщение фиксировано карточкой:

```text
L01: scaffold module 1
```

Порядок:

```bash
git init
git add README.md .gitignore notes/permissions.md notes/session-log.md src/.gitkeep tests/.gitkeep
git commit -m "L01: scaffold module 1"
git status --porcelain
git log --oneline
```

**Важно:** это команда для вашей практики с шестью файлами. В демонстрации преподаватель может показывать Git на отдельной папке с другим набором файлов. У двух отдельных репозиториев хеши коммитов могут различаться из-за метаданных: сравнивайте дерево и сообщение коммита, а не хеш.

**Студенту не нужно повторять этот запрос.** Это демонстрация преподавателя в одноразовой папке, не в вашей рабочей копии.

```text

```

**Предскажите:** откажет, попросит разрешение, выполнит или не поймёт область?

## S15. Если граница нарушена

Возможные исходы:

1. Инструмент отказался или попросил разрешение — преподаватель отклонил и записал.
2. Инструмент выполнил действие — преподаватель остановил работу, удалил файл, проверил окружение и записал инцидент.
3. Инструмент не понял область — преподаватель уточнил формулировку и записал, что граница была задана недостаточно явно.

Порядок:

```text
остановить → записать → безопасно отменить → проверить следы → сообщить → внести в журнал
```

Не продолжайте работу «как будто ничего не было».

## S16. Приёмка дерева

Ожидаемое дерево:

```text
README.md
.gitignore
notes/permissions.md
notes/session-log.md
src/.gitkeep
tests/.gitkeep
```

Проверка дерева до коммита:

```bash
find . -type f -not -path './.git/*' | sort
```

`git status` появится после `git init`, `git log` — после коммита; это S17. В пустой папке до инициализации они не работают.

Лишние файлы — не «полезный бонус», а отклонение от карточки. Удалите их и запишите причину.

---

## S17. Чистое дерево и коммит

После коммита:

- `git status --porcelain` пуст;
- `git log --oneline` показывает сообщение `L01: scaffold module 1`;
- все шесть файлов добавлены в Git;
- `.gitignore` содержит `__pycache__/`, `*.pyc`, `.DS_Store`.

Что это **не** доказывает:

- что файлы содержат правильный текст;
- что агент не выходил за область;
- что журнал разрешений заполнен.

Эти вещи проверяются отдельно — глазами и по журналу.

## S18. Если что-то пошло не так

| Симптом | Действие |
|---|---|
| Авто-подтверждение, запросов нет | Записать ограничение, проверять diff вручную |
| Появился лишний файл | Удалить, записать причину, повторить проверку |
| Файл появился вне папки | Остановить, удалить, проверить следы, записать инцидент |
| Предложен `git config --global` | Отклонить, записать |
| Коммит не создаётся | Проверить `git status` и локальные имя/почту, не менять глобальные настройки |
| Инструмент недоступен | Записать ошибку и время, выполнить доступную часть, не выдумывать вторую попытку |

При повторе — новый номер попытки и причина. Старую запись не удалять.

Откройте **новый сеанс**, укажите рабочую папку и передайте запрос:

## S24. Практика 46–61: проверка и коммит

В каждой копии:

```bash
find . -type f -not -path './.git/*' | sort
```

Сверьте дерево с шестью файлами из S16. Лишние файлы удалите и запишите причину.

Первый коммит:

```bash
git init
git add README.md .gitignore notes/permissions.md notes/session-log.md src/.gitkeep tests/.gitkeep
git commit -m "L01: scaffold module 1"
git status --porcelain
git log --oneline
```

`git status --porcelain` должен быть пустым. Коммит нужен в каждой копии: первичная — для сдачи, вторая — для сравнения. Если вторая копия не завершена, запишите это как ограничение. Хеши двух коммитов могут различаться — это нормально; сравнивайте дерево и сообщение.

## S25. Практика 61–69: журнал и сравнение

Заполните раздел L01 в [`../shared/run_journal.md`](../shared/run_journal.md):

- дерево в каждой копии;
- хеш, сообщение и `git status` каждого коммита;
- события разрешений: что запрошено, что разрешено, что отклонено;
- для L01 новые файлы до `git add` могут не отображаться в `git diff` — используйте `git status` и `find`;
- как проверяли отсутствие изменений вне области;
- первичная среда и почему она назначена заранее;
- одинаковые снимок, запрос и критерии;
- что можно утверждать по двум попыткам, а что нельзя.

Сравнение ограничено: один снимок, один запрос, две среды. Нельзя утверждать, что инструмент «всегда лучше» или «всегда безопаснее».
