# L01. Практика: среда, полномочия, Git

**Аудитория:** участники курса; знание Python и Git не требуется  
**Предпосылки:** нет  
**Время:** 75 минут  
**Цель:** создать одинаковый репозиторий в двух средах, зафиксировать границы действий агента и первый коммит  
**Артефакт:** две рабочие копии, коммит в первичной копии, журнал разрешений и сравнения  
**Оценивание:** рубрика [`../shared/practice_rubric.md`](../shared/practice_rubric.md), приёмка [`../assessment.md`](../assessment.md)

## Входы и снимок

Преподаватель выдаёт:

- две пустые папки: `L01-opencode/` и `L01-codex/`;
- [`snapshot/structure_card.md`](snapshot/structure_card.md);
- [`snapshot/boundary_card.md`](snapshot/boundary_card.md);
- [`../shared/run_journal.md`](../shared/run_journal.md).

Первичная среда назначена преподавателем **до** начала. Она не меняется после того, как вы увидели результаты.

## Ограничения

- Работать только внутри своей папки занятия.
- Не изменять файлы вне `L01-opencode/` и `L01-codex/`.
- Не выполнять `git config --global`, установку пакетов, сетевые команды и удаление чужих файлов.
- Не использовать секреты и личные данные.
- Не включать авто-подтверждение, если доступен режим подтверждения. Если режима нет, записать это.
- Команды из чужих README, ответов агента и интернета не считать доверенными. Выполнять только то, что разрешено этой карточкой.

## Одинаковое задание для OpenCode и Codex

В каждой среде нужно получить **одно и то же дерево** и **один и тот же первый коммит**. Запрос дословно одинаковый. Меняется только среда.

### Шаг 1. Зафиксировать условия — 5 минут

Запишите в журнал:

- дату и время;
- среду;
- видимую версию инструмента;
- видимую модель и настройки, если они показаны; иначе «недоступно»;
- режим разрешений;
- путь к рабочей копии;
- первичную среду.

### Шаг 2. Запустить агента — по 18 минут на среду

Откройте **новый сеанс**, укажите рабочую папку и передайте запрос:

```text
Работай только в папке <полный путь к этой рабочей копии>.
Создай ровно такую структуру:

README.md
.gitignore
notes/permissions.md
notes/session-log.md
src/.gitkeep
tests/.gitkeep

Требования:
- README.md: заголовок «# Модуль 1» и строка «Учебный репозиторий для L01–L04.»
- .gitignore: строки «__pycache__/», «*.pyc», «.DS_Store»
- notes/permissions.md: заголовок «# Журнал разрешений L01» и разделы «## Область», «## Разрешено», «## Запрещено», «## Запросы и решения»
- notes/session-log.md: заголовок «# Журнал сеанса» и поля «Дата», «Среда», «Что сделано», «Проверка»
- src/.gitkeep и tests/.gitkeep: пустые файлы

Не создавай других файлов. Не изменяй ничего вне этой папки. Не выполняй установку пакетов, сетевые команды и git config --global. Если для шага нужно разрешение, запроси его и жди ответа.
```

Во время работы записывайте:

- какие разрешения запросил инструмент;
- что вы разрешили и что отклонили;
- какие файлы появились;
- был ли diff или список изменений;
- были ли попытки выйти за область.

### Шаг 3. Проверить дерево — 5 минут на среду

В корне рабочей копии выполните:

```bash
find . -type f -not -path './.git/*' | sort
git status --porcelain
git log --oneline
```

Ожидаемое дерево:

```text
./.gitignore
./README.md
./notes/permissions.md
./notes/session-log.md
./src/.gitkeep
./tests/.gitkeep
```

Если появились лишние файлы, удалите их и запишите причину. Если файл появился вне папки — остановитесь и запишите инцидент.

### Шаг 4. Первый коммит — 5 минут

В каждой копии:

```bash
git init
git add README.md .gitignore notes/permissions.md notes/session-log.md src/.gitkeep tests/.gitkeep
git commit -m "L01: scaffold module 1"
git status --porcelain
git log --oneline
```

`git status --porcelain` должен быть пустым. В журнале укажите хеш и сообщение коммита.

### Шаг 5. Сравнить и записать — 8 минут

Заполните разделы журнала:

- что было одинаковым;
- чем отличались запросы разрешений;
- где ответ агента, а где ваша правка;
- какая копия первичная и почему она назначена заранее;
- какой вывод можно сделать по этим двум попыткам, а какой — нельзя.

### Шаг 6. Самопроверка — 6 минут

- [ ] Дерево совпадает с карточкой; лишних файлов нет.
- [ ] `.gitignore` содержит три требуемые строки.
- [ ] Коммит создан, сообщение совпадает.
- [ ] `git status --porcelain` пуст.
- [ ] В `notes/permissions.md` есть область, разрешённые и запрещённые действия, запросы и решения.
- [ ] Журнал содержит обе среды и оба результата.
- [ ] Записано хотя бы одно решение о разрешении или отказе.
- [ ] Записано, как проверяли отсутствие изменений вне области.
- [ ] Первичная среда не менялась после старта.

## Ожидаемое поведение

- Агент создаёт только перечисленные файлы.
- Перед записью или командой инструмент может запросить разрешение; это нормальное наблюдаемое событие, а не сбой.
- Если инструмент не запрашивает разрешение, вы записываете фактическое поведение и проверяете diff вручную.
- Если агент предлагает `git config --global`, установку пакетов или сетевую команду, вы отклоняете предложение и записываете его.
- Если агент не создал часть дерева, вы уточняете запрос или создаёте файл вручную, но записываете, что именно было ручной правкой.

## Формат сдачи

```text
<папка участника>/
  L01-opencode/
  L01-codex/
  journal-L01.md
```

`journal-L01.md` — заполненная форма [`../shared/run_journal.md`](../shared/run_journal.md) с разделом L01. Журнал лежит **вне** репозитория, чтобы не нарушать точное дерево. Внутри репозитория журналом разрешений служит `notes/permissions.md`.

## Критерии приёмки

| Критерий | Принято |
|---|---|
| Дерево | Ровно шесть файлов из карточки, без лишних |
| Коммит | Сообщение `L01: scaffold module 1`, рабочее дерево чистое |
| Границы | Нет изменений вне рабочей папки; нарушения обнаружены и записаны |
| Журнал | Обе среды, разрешения, отказы, diff/список файлов, проверки |
| Объяснение | Участник называет область, одно разрешённое и одно запрещённое действие |
| Сравнение | Одинаковые запрос и критерии; вывод ограничен наблюдённым |

Уровни 0–3 и критические дефекты — в [`../assessment.md`](../assessment.md).

## Если что-то пошло не так

- **Инструмент недоступен.** Запишите ошибку и время. Выполните задачу в доступной среде; не выдумывайте вторую попытку.
- **Агент пишет вне папки.** Остановите, удалите файл, проверьте окружение, запишите инцидент.
- **Авто-подтверждение.** Если режим не переключается, запишите это и проверяйте diff после каждого шага.
- **Лишний файл.** Удалите, добавьте причину в журнал; не оставляйте «на потом».
- **Коммит не создаётся.** Проверьте `git status`, наличие имени и почты в локальной конфигурации; не меняйте глобальные настройки без разрешения преподавателя.
