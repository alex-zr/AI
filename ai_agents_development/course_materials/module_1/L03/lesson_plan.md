## Содержание

Исправление B2 требует строкового метода, но не ветвления. Знать точный метод заранее не нужно: участник может получить вариант у агента и проверить его тремя тестами. Оценивается не запоминание метода, а способность увидеть дефект, сохранить красный запуск и подтвердить исправление.

### 1. Тест как проверяемое поведение

Запуск отвечает на вопрос «что получилось». Тест отвечает на вопрос «совпадает ли полученное с заранее заданным поведением». Хороший тест:

- имеет один понятный вход;
- содержит ожидаемый результат;
- падает, если поведение нарушено;
- не зависит от порядка запуска и внешних файлов.

На L03 проверяются только три поведения из `BEHAVIORS.md`. Не нужно добавлять проверки типов, `None`, чисел и других случаев: это были бы новые требования.

### 2. Анатомия `unittest`

```python
import unittest

from shout import shout


class ShoutTest(unittest.TestCase):
    def test_plain_text(self):
        self.assertEqual(shout("ada"), "ADA!")


if __name__ == "__main__":
    unittest.main()
```

- `TestCase` — класс с тестами;
- имя метода начинается с `test_`;
- `assertEqual(фактическое, ожидаемое)` сравнивает значения;
- запуск из корня: `python3 -m unittest discover -s tests -v`;
- `-v` показывает имена тестов.

### 3. Демонстрация 1: красный запуск

Файл `shout.py` с дефектом:

```python
def shout(text):
    return text + "!"
```

Тест ожидает `ADA!` для `"ada"` и `"ADA"`. Запуск падает на первом случае. Преподаватель читает сообщение:

- имя теста;
- фактическое значение;
- ожидаемое значение;
- строку с `assertEqual`.

Вывод: падение — полезное свидетельство, если оно относится к проверяемому поведению.

### 4. Демонстрация 2: минимальная правка

```python
def shout(text):
    return text.upper() + "!"
```

Запуск зелёный. Diff показывает одну строку. Тесты не изменялись. Обсудить: почему нельзя «поправить» ожидаемое значение, если поведение задано карточкой.

### 5. Демонстрация 3: слабый тест

Показать тест, который всегда проходит:

```python
def test_nothing(self):
    self.assertTrue(True)
```

Он не проверяет поведение. Формально «зелёный», но не ловит дефект. Проверка качества: тест должен упасть на исходном дефектном файле. Именно это проверяет `verify_l03.py`.

Второй слабый вариант — тест, который проверяет только B1 или только B3. Он проходит на дефекте, потому что дефект находится в B2. Три поведения требуют трёх тестов.

### 6. Запрос агенту

Запрос должен:

- разрешать менять только `greet.py` и `tests/test_greet.py`;
- запрещать менять `BEHAVIORS.md`;
- требовать ровно три теста;
- требовать красный запуск до правки и зелёный после;
- требовать diff.

## Вопросы на разбор

1. **Что именно проверяет каждый из трёх тестов?**  
   Ожидаемые элементы: B1 — обычное имя; B2 — пробелы по краям; B3 — пробел между частями имени; по одному тесту на поведение.

2. **Почему красный запуск обязателен?**  
   Ожидаемые элементы: он показывает, что тест способен упасть; иначе нельзя отличить проверку от подгонки; после правки зелёный запуск подтверждает исправление.

3. **Что считать минимальным исправлением?**  
   Ожидаемые элементы: изменение только `greet.py`; тесты не ослаблены; лишние функции и зависимости не добавлены; diff объясним.

## Типичные сбои

| Сбой | Признак | Действие |
|---|---|---|
| Тест всегда зелёный | На baseline тоже проходит | Добавить проверку поведения, а не факта |
| Тест проверяет не то | Ожидание не из `BEHAVIORS.md` | Вернуть к трём поведениям |
| Тест изменён после падения | Diff в тестах | Отклонить, восстановить, записать |
| Исправление переписало функцию | Большой diff | Свести к минимальной правке |
| `ModuleNotFoundError` | Запуск не из корня или нет `greet.py` | Проверить путь и `sys.path` |
| Все тесты падают | Ошибка импорта или синтаксиса | Прочитать traceback, исправить причину |

## Проверка и свидетельства

1. Красный запуск: команда, вывод, имя упавшего теста — до правки.
2. Зелёный запуск: команда, вывод — после правки.
3. `git diff` — только `greet.py` и `tests/test_greet.py`.
4. `python3 teacher_key/verify_l03.py <путь-к-копии>` — тесты падают на baseline и проходят на решении.
5. Журнал: три поведения, три теста, «до/после», diff.
