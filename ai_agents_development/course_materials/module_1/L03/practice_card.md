# L03. Практика: тест и исправление

**Аудитория:** участники после L02  
**Предпосылки:** L01 — Git; L02 — функция, запуск, ожидаемый вывод  
**Время:** 75 минут  
**Цель:** написать три теста, увидеть красный запуск, исправить дефект и подтвердить зелёным  
**Артефакт:** три теста, журнал «до/после», diff  
**Оценивание:** [`../shared/practice_rubric.md`](../shared/practice_rubric.md), [`../assessment.md`](../assessment.md)

## Входы и снимок

Преподаватель выдаёт две одинаковые копии снимка:

```text
L03-opencode/
  greet.py          функция с дефектом
  BEHAVIORS.md      три обязательных поведения
  tests/            пустая папка для вашего теста
L03-codex/
  то же самое
```

Если копии уже содержат базовый коммит, не повторяйте `git init`; проверьте `git log -1`. Если коммита нет, создайте его с сообщением `L03: baseline`.

## Три поведения

Из [`snapshot/BEHAVIORS.md`](snapshot/BEHAVIORS.md):

| № | Вход | Ожидаемый результат |
|---|---|---|
| B1 | `greet("Ada")` | `Привет, Ada!` |
| B2 | `greet("  Ada  ")` | `Привет, Ada!` |
| B3 | `greet("Ada Lovelace")` | `Привет, Ada Lovelace!` |

Другие входы в этом задании не проверяются. Не добавляйте требования о числах, `None`, списках и других типах.

## Ограничения

- Менять только `greet.py` и `tests/test_greet.py`.
- Не менять `BEHAVIORS.md`.
- Не добавлять зависимости.
- Не ослаблять тесты после падения.
- Не выходить за рабочую копию.
- Запрос в обеих средах — дословно одинаковый.

## Одинаковое задание для OpenCode и Codex

### Шаг 1. Подготовка — 5 минут

Запишите в журнал: среда, версия, видимая модель/настройки или «недоступно», путь к копии, базовый коммит, первичную среду.

### Шаг 2. Запуск агента — по 17 минут

Новый сеанс. Запрос:

```text
В этой рабочей копии есть greet.py с дефектом и BEHAVIORS.md с тремя поведениями.
Не меняй BEHAVIORS.md и не добавляй зависимости.
Сначала создай tests/test_greet.py на unittest: ровно три теста, по одному на B1, B2, B3.
Запусти python3 -m unittest discover -s tests -v и покажи полный вывод.
Затем исправь только greet.py минимально, чтобы все три теста прошли.
Снова запусти тесты и покажи полный вывод и git diff.
```

### Шаг 3. Записать красный запуск — до исправления

Команда:

```bash
python3 -m unittest discover -s tests -v
```

Ожидается: хотя бы один тест падает. Сохраните в журнал:

- команду;
- имя упавшего теста;
- фактическое и ожидаемое значение;
- код возврата (ненулевой).

Если все тесты сразу зелёные, остановитесь: тест не ловит дефект. Перепишите тест, а не реализацию.

### Шаг 4. Исправить и проверить — после красного

```bash
python3 -m unittest discover -s tests -v
echo "код возврата: $?"
git diff
```

Ожидается: три теста, код 0, изменения только в `greet.py` и `tests/test_greet.py`.

### Шаг 5. Сравнить и записать — 10 минут

Заполните раздел L03 формы [`../shared/run_journal.md`](../shared/run_journal.md):

- три поведения и три теста;
- красный вывод;
- зелёный вывод;
- diff;
- что было ответом агента, а что ручной правкой;
- чем отличались среды.

### Шаг 6. Самопроверка — 6 минут

- [ ] В `tests/test_greet.py` ровно три теста, по одному на B1–B3.
- [ ] Красный запуск сохранён до исправления.
- [ ] Хотя бы один тест падал на исходном `greet.py`.
- [ ] После исправления все три проходят.
- [ ] `git diff` не меняет `BEHAVIORS.md` и не ослабляет тесты.
- [ ] Журнал содержит обе среды и оба результата.

## Заготовка теста

Можно начать с такого файла и заменить заглушки проверками:

```python
import unittest

from greet import greet


class GreetTest(unittest.TestCase):
    def test_behavior_1(self):
        self.fail("Замените на проверку B1")

    def test_behavior_2(self):
        self.fail("Замените на проверку B2")

    def test_behavior_3(self):
        self.fail("Замените на проверку B3")


if __name__ == "__main__":
    unittest.main()
```

Заглушка `self.fail` специально падает: она не должна остаться в сдаче.

## Ожидаемое поведение

- B1 и B3 проходят на исходной функции; B2 падает.
- После исправления все три проходят.
- Тест, который проверяет только B1 или только B3, не ловит дефект B2 и не принимается.
- Если агент меняет ожидаемые значения под фактический вывод, это подгонка; верните требования из `BEHAVIORS.md`.

## Формат сдачи

```text
<папка участника>/
  L03-opencode/
  L03-codex/
  journal-L03.md
```

В первичной копии — `greet.py`, `tests/test_greet.py`, базовый и итоговый коммиты. Журнал лежит вне репозитория.

## Критерии приёмки

| Критерий | Принято |
|---|---|
| Тесты | Три теста, по одному на B1–B3 |
| Красный | Хотя бы один тест падает на исходном файле |
| Зелёный | Все три проходят после исправления |
| Baseline | `verify_l03.py` подтверждает падение на baseline |
| Границы | Изменены только `greet.py` и `tests/test_greet.py` |
| Diff | Минимальный, тесты не ослаблены |
| Журнал | «До/после», команды, вывод, объяснение |

## Если что-то пошло не так

- **Все тесты зелёные сразу** — тест не ловит дефект; проверьте B2.
- **`ModuleNotFoundError`** — запускайте из корня копии, где лежит `greet.py`.
- **`IndentationError`** — проверьте отступы в тестовом классе.
- **Тест падает после исправления** — прочитайте фактическое значение; возможно, исправление неполное.
- **Агент изменил тест** — верните тест к требованиям, запишите отклонение.
- **Инструмент недоступен** — запишите ошибку; выполните задачу в доступной среде, не выдумывайте вторую попытку.
