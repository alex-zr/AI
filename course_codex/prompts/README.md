# Набор промптов для разработки курса Core Python

**Статус:** рабочая последовательность v1.1, 2026-11-03.
**Назначение:** управлять созданием курса отдельными проверяемыми шагами и возвращаться к любому шагу без потери контекста.

Промпты — это инструкции для работы. Источники истины о курсе находятся в `planning/`, учебные материалы — в каталогах модулей, текущее состояние — в `status.md`. Исходные формулировки сохранены в `../prompts.txt`; они не переписаны этим набором. Постоянные правила проекта остаются в `../AGENTS.md`. Не копируйте их целиком в каждый промпт.

Файл `prompts.txt` содержит исходные запросы в обратном порядке и с прежними путями. В этом наборе пути приведены к текущему репозиторию: спецификация и план лежат в `planning/`, а `dependencies.yaml` сейчас отсутствует. В шаге 04 зависимости собираются из `planning/topic_tree.yaml` в контекст конкретного модуля; отдельный глобальный файл зависимостей не требуется.

## Как запускать

В новом чате достаточно передать один промпт и параметры:

> Выполни `prompts/05-theory.md` для `MODULE_ID=S02-M07`. Используй текущие файлы репозитория. Остановись на теории этого модуля.

Для шага 03 укажите `STAGE_ID=S03`; для шага 05 при большой теме можно добавить `SUBTOPIC_ID=...`; для шага 07A — `MODULE_ID=...` и при необходимости `OUTPUT_FORMAT=md|pdf|pptx`; для шага 10 — `TARGET=...` и конкретное изменение. Если файл результата уже существует, промпт требует оценить его состояние и редактировать адресно, сохраняя ID. В одном запуске выполняется **один указанный шаг**, поэтому пользователь видит результат и может поправить направление до следующего.

## Учебный цикл модуля

Подробная теория создаётся по малым подтемам, без потери механизмов и нюансов. Для занятия на её основе собирается минимальный достаточный блок слайдов по каждой подтеме: цель, модель, точное правило, исполняемый пример, типичная ошибка. Сразу после блока следует простая задача. Средние, сложные и задачи формата собеседования появляются позже, когда изучены все их предпосылки; в конце модуля есть интеграционное закрепление. Одна подтема не обязана содержать все четыре категории задач.

`slides.md` — редактируемый исходник набора слайдов. `slides_plan.md` хранит карту соответствия «результат → слайд → задача» и не попадает в презентацию. PDF или PPTX создаётся по явному параметру, если доступен экспорт; наличие Markdown-исходника само по себе не означает, что экспорт проверен. Учебное решение задачи не показывается до её постановки. Время объясняющих слайдов учитывается как теория, время самостоятельного решения — как практика, оценочное интервью — как контроль.

Новая цепочка промптов задаёт слайды как обязательный результат разработки каждого модуля. Действующая `planning/course_spec.md` пока перечисляет учебные материалы без отдельного обязательного требования к презентациям. Для формального закрепления этого требования в спецификации нужно отдельно запустить шаг 01 на её адресный пересмотр; утверждённый план и уже созданные материалы сейчас автоматически не меняются.

## Возврат к прежнему шагу

1. Запустите [10-revision.md](10-revision.md), указав целевой файл или ID и нужное изменение.
2. Получите список затронутых артефактов и внесите только необходимые исправления. Не перегенерируйте весь курс из-за локальной ошибки.
3. Повторно запустите [09-quality-review.md](09-quality-review.md) для затронутых частей.
4. Используйте Git для истории версий промптов и материалов. ID промпта сохраняется при редакционной правке; существенное изменение требований отмечается в заголовке версией и краткой записью внизу файла.

Не считайте старое сообщение в чате единственным носителем решения: нужное состояние должно быть видно из файлов и `status.md`. Если описание в промпте расходится с утверждённым планом, сначала разрешите расхождение через шаг 10.

## Правило качества промпта

Каждый файл задаёт один результат, нужные источники, границы, проверку готовности и место сохранения. Общие правила языка, технической точности и файлов уже заданы в `AGENTS.md` и `planning/course_spec.md`; промпты добавляют только требования своего шага. Этот подход согласуется с [официальными рекомендациями OpenAI о контекстных инструкциях для Codex](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) и [описанием поэтапной работы с файлами](https://developers.openai.com/cookbook/examples/codex/iterating-development-workflows-with-codex).
