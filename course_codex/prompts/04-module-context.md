# PROMPT-04 v1.1 — Контекст одного модуля

**Параметр:** `MODULE_ID=<Sxx-Myy>`. **Результат:** `planning/module_context/<MODULE_ID>.md`.

Подготовь краткий, проверяемый входной конспект для разработки материалов модуля `MODULE_ID`. Прочитай `AGENTS.md`, `planning/course_spec.md`, нужный модуль и его предварительные ID в `planning/topic_tree.yaml`, соответствующий раздел `planning/curriculum.md` и `status.md`. Если предыдущие учебные материалы существуют, используй их; если нет, опирайся на результаты и понятия плана и обозначь, что это реконструкция, а не доказательство фактического изучения.

Составь файл с разделами: ID и название; статус плана; предварительные знания по ID; короткий конспект понятий, доступных ученику; конкретные запреты на использование непокрытых знаний без объяснения; границы модуля; его подтемы и результаты; рекомендуемый порядок коротких объясняющих блоков и точек закрепления; обязательные поздние повторения; ссылки на реальные исходные файлы. Разделяй «запланировано», «материал создан» и «ученик освоил»: последнее нельзя утверждать без данных оценки.

Если `planning/dependencies.yaml` появится позже, сверяй его с `topic_tree.yaml`. Если файла нет, не требуй его и не создавай вторую копию графа зависимостей: `topic_tree.yaml` уже хранит предварительные ID. Не создавай теорию, вопросы, задачи или контроль. Проверь, что все упомянутые ID существуют, а пути ведут к реальным файлам. Обнови `status.md` и остановись.

**История:** v1.0 — устраняет отсутствующие `dependencies.yaml` и «конспект уже изученных тем» из исходного промпта теории.

**v1.1:** контекст модуля фиксирует последовательность малых объясняющих блоков и практики без создания самих материалов.
