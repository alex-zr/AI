# PROMPT-07A v1.0 — Слайды одного модуля с практикой

**Параметры:** `MODULE_ID=<Sxx-Myy>`; необязательно `OUTPUT_FORMAT=md|pdf|pptx` (по умолчанию `md`). **Результат:** `<MODULE_ID>/slides_plan.md` — карта презентации и `<MODULE_ID>/slides.md` — исходник слайдов в Markdown; при запрошенном формате и доступном средстве экспорта — также PDF или PPTX в том же каталоге. Не создавай презентацию другого модуля.

Ты — автор технических презентаций и преподаватель Python. Прочитай `AGENTS.md`, `planning/course_spec.md`, модуль и его зависимости в `planning/topic_tree.yaml`, `planning/module_context/<MODULE_ID>.md` при наличии, полную теорию модуля, `<MODULE_ID>/exercises.md` и `<MODULE_ID>/interview.md` при наличии. Если теория или задачи отсутствуют для обязательной подтемы, подготовь только покрытую часть и явно пометь презентацию как незавершённую; не выдумывай отсутствующий учебный материал.

Сначала составь в `slides_plan.md` карту слайдов: порядок подтем, их ID и результаты, предварительные знания, ID слайдов, ID задач и момент их появления. Затем создай читаемую презентацию в `slides.md`; этот файл начинается с первого слайда, без служебной карты. Используй один разделитель `---` между слайдами, один стабильный ID вида `<MODULE_ID>-SL001` в HTML-комментарии каждого слайда и короткий заголовок. Выбери минимальное число слайдов, достаточное для объяснения обязательных результатов; ориентир — 3–6 основных слайдов на небольшую подтему, но добавляй слайды, если иначе исчезают механизм, пример или существенное ограничение. Не уплотняй текст до нечитаемости. Полная подробная теория остаётся в `theory_old.md` и файлах подтем; слайды содержат учебную последовательность, а не её копию. Если подробное объяснение важно преподавателю, добавь краткие заметки докладчика (speaker notes) и ссылку на раздел теории.

Для каждой подтемы выстрой цикл: цель → интуитивная модель → точное правило и, где важно, внутренний механизм → небольшой исполняемый пример с пошаговым разбором → типичная ошибка или граница применимости → посильная простая задача сразу после минимального объясняющего блока. После достаточных предпосылок поставь средние, сложные и задачи формата собеседования; завершай модуль интеграционным блоком. Задачи на слайдах должны иметь ID и понятное условие, достаточное для начала работы, плюс ссылку на полный контракт в `exercises.md`; не раскрывай решения до постановки задачи. Для каждой категории укажи плановые минуты самостоятельной работы и формат обсуждения. Не превращай слайды задач в тесты с готовым ответом.

Отдельно маркируй гарантии языка Python, стандартную библиотеку и детали CPython, указывай версию там, где она влияет на результат. Используй только уже объяснённые понятия. Для каждого примера укажи ожидаемый результат и проверь исполнение на целевой версии; не помещай на один слайд код, который нельзя прочитать с экрана. Иллюстрации и схемы используй только когда они объясняют механизм; добавляй текстовую альтернативу к значимой схеме.

Проверь перед сдачей: у каждой обязательной подтемы есть свои слайды и ближайшая посильная задача; все ID слайдов уникальны; каждое задание со слайда существует в `exercises.md`; четыре категории задач представлены в модуле либо дефицит явно объяснён; порядок соответствует зависимостям; по исходнику можно провести занятие без устных догадок о содержании. Если экспорт доступен, проверь отрисовку: переносы, размер кода, контраст, отсутствие обрезанного текста и порядок слайдов. Если экспорта нет, сохрани полноценный `slides.md` и запиши ограничение, не объявляя PDF/PPTX готовым. Отметь плановые минуты слайдов в категории «теория», самостоятельных задач — в «практика»; интервью-контроль учитывай отдельно, не считай одну и ту же минуту дважды. Обнови `status.md` и остановись.

**История:** v1.0 — добавлена презентация как отдельный результат модуля между задачами и контролем, с циклом объяснения и закрепления.
