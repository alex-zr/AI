# PROMPT-01 v1.1 — Спецификация курса

**Выполнять:** при создании или явном пересмотре спецификации. **Результат:** `planning/course_spec.md`.

Ты — методист технического образования, Senior Python Developer и технический интервьюер. Разработай спецификацию полной программы Core Python для человека без опыта программирования до уровня Junior Interview Ready.

Сначала прочитай `AGENTS.md`, `planning/initial_modules.md` и существующую `planning/course_spec.md`, если она есть. При обновлении сохрани уже принятые решения, а каждое предлагаемое изменение обязательного критерия перечисли и обоснуй. Не переписывай документ без причины.

Спецификация должна определить:

1. Проверяемые знания и навыки выпускника и результаты уровней Beginner, Foundation, Junior, Junior Interview Ready.
2. Целевую версию Python и границу между языком Python и реализацией CPython.
3. Границы Core Python и вынесенные за них темы.
4. Виды материалов, включая подробную теорию малых подтем, слайды по каждому модулю и задачи после объясняющих блоков; распределение плановых минут: 50% теория и механизмы, 30% практика и анализ кода, 20% интервью и контроль.
5. Критерии качества теории, вопросов, задач, примеров и источников.
6. Измеримые условия прохождения модуля и итоговой готовности.
7. Повторение, пробные собеседования, техническую проверку, стандарт ID и файлов.

Для каждого решения укажи, является ли оно обязательным требованием или рекомендацией. Если поведение Python зависит от версии или реализации, опирайся на актуальные официальные разделы документации целевой версии. Не создавай учебный план, уроки, банк вопросов или задачи.

Сохрани результат в `planning/course_spec.md`. Проверь, что все десять пунктов исходной постановки покрыты, критерии измеримы, а противоречий внутри спецификации нет. Обнови `status.md`: что изменено, что проверено, какие решения ещё открыты. Остановись после этого шага.

**История:** v1.0 — исходный запрос из `prompts.txt` приведён к пути текущего проекта и правилу адресного пересмотра.

**v1.1:** при явном пересмотре спецификации предлагает закрепить слайды и последовательное закрепление как требование; уже существующие обязательные критерии нельзя менять молча.
