## 2. Предварительные знания и входной конспект

По уже пройденным темам достаточно помнить следующее:

- Программа создаёт значения и связывает с ними имена через `=`. Повторное присваивание меняет связь имени с объектом. `type(value)` показывает тип значения.
- Строковый литерал `"кот"` даёт значение типа `str`. Известны кавычки, экранирование `\n`, сложение строк через `+`, `len()`, `print()`, `input()` и простая f-строка.
- `if` выбирает ветвь по истинности значения; `for` последовательно обрабатывает элементы. `==` сравнивает значения, `is` — идентичность объектов. Эти операции не взаимозаменяемы.
- Изменяемый объект можно изменить, сохранив тот же объект; неизменяемый — нельзя. Строки неизменяемы. Если операция даёт другой текст, результат нужно связать с именем.
- Оценка `O(n)` описывает рост числа шагов при росте входа `n`, а не точное время работы. В этом модуле `n` обычно означает длину текста в кодовых точках, если не сказано иное.
- `IndexError` и `ValueError` пока достаточно понимать как названия ошибок и читать их в конце traceback. Полная иерархия исключений изучается позднее.

Здесь `split()` впервые возвращает список (list). Для понимания достаточно знать: список — упорядоченный контейнер значений, записываемый как `["a", "b"]`. Его устройство и изменяемость подробно изучаются в S02-M07. Здесь не требуется теория итераторов, файлов или модулей.

## 3. Интуитивная модель

Представьте строку как ряд пронумерованных ячеек. В каждой ячейке находится **одна кодовая точка Unicode**. Индекс берёт одну ячейку; срез выбирает ряд ячеек по правилу. `len()` считает ячейки. На экране один видимый знак иногда складывается из нескольких кодовых точек, поэтому число ячеек может отличаться от числа увиденных знаков.

Строка похожа на написанный чернилами текст: её нельзя «поправить на месте». `replace()` или `upper()` дают результат с изменённым содержимым; старое значение остаётся прежним. Когда текст надо отправить в файл или по сети, необходим другой вопрос: **какими байтами его представить?** На него отвечает кодировка (encoding), например UTF-8.

## 4. Формальные определения и границы модели

| Термин | Определение для этого модуля |
| --- | --- |
| Строка (`str`) | Неизменяемая последовательность кодовых точек Unicode в Python 3.14. |
| Кодовая точка (code point) | Числовое значение, назначенное в пространстве Unicode; в описании пишут, например, `U+1F600`. |
| Глиф (glyph) | Видимое начертание на экране или бумаге; зависит от системы отображения и шрифта. Не равен автоматически одному элементу `str`. |
| Индекс (index) | Целая позиция отдельного элемента последовательности. |
| Срез (slice) | Выбор элементов от начальной границы до исключённой конечной с указанным шагом. |
| Подстрока (substring) | Непрерывный фрагмент текста, который можно искать в другом тексте. |
| Байты (`bytes`) | Неизменяемая последовательность целых чисел от 0 до 255, обычно представляющая двоичные данные. |
| Кодировка (encoding) | Правила отображения текста в байты и обратного восстановления; UTF-8 — конкретная кодировка Unicode. |

На уровне языка `str` — последовательность текстовых элементов. Это **не обещание** хранить каждую кодовую точку в одном байте, двух байтах или четырёх байтах; способ хранения — деталь реализации. Правила последовательности, Unicode и строкового типа описаны в [Unicode HOWTO](https://docs.python.org/3.14/howto/unicode.html#introduction-to-unicode) и [Text Sequence Type — str](https://docs.python.org/3.14/library/stdtypes.html#text-sequence-type-str).

## 5. Подробная теория по подтемам

### S02-M06-T003-P01 — Строка как последовательность

**Результат подтемы:** по данному `str` определить длину, значение допустимого положительного или отрицательного индекса, предсказать `IndexError` и объяснить, почему длина может не совпадать с количеством видимых знаков.

**Что и зачем.** Индексация нужна, когда важна позиция: проверить первый знак, взять последний или пройти текст посимвольно. У строки длины `n` положительные индексы идут от `0` до `n - 1`. Отрицательные — от `-n` до `-1`; `-1` обозначает последний элемент. Индексация возвращает строку длины один, а не отдельный тип `char`: отдельного встроенного символьного типа в Python нет. `len("") == 0`, и у пустой строки нет доступных индексов.

`len(s)` считает кодовые точки, а не байты кодировки UTF-8 и не ширину текста на экране. Сочетание буквы и комбинируемого знака может выглядеть как один знак, но состоять из двух элементов строки. Некоторые эмодзи составлены из нескольких кодовых точек. Ровно одна кодовая точка не означает ровно одну экранную колонку. Это важно для обрезки интерфейсного текста и ограничения «числа символов». Более сложное понятие «графемный кластер» (grapheme cluster) означает воспринимаемый пользователем знак; обычная индексация `str` не выделяет такие кластеры. Здесь мы лишь фиксируем границу механизма, не реализуя графемную сегментацию. [Источник: Unicode HOWTO](https://docs.python.org/3.14/howto/unicode.html#introduction-to-unicode).

**Правила доступа.** Для `s[i]` Python проверяет, есть ли элемент с данным индексом. Если нет, возникает `IndexError`. Отрицательные индексы удобны, но `s[-1]` на пустой строке также ошибочен. Для первого или последнего знака нужно заранее знать, что строка не пуста: `if s: ...`. Строка поддерживает `for ch in s`, `ch in s` и сравнение строк; `in` проверяет и многосимвольную подстроку. Сравнение `==` проверяет текстовое значение, а `is` — идентичность объектов. Порядковое сравнение строк лексикографическое по кодовым точкам, не «словарное» по правилам человеческого языка: `"Z" < "a"` истинно, но это не правило алфавитной сортировки слов. [Источник: Common Sequence Operations](https://docs.python.org/3.14/library/stdtypes.html#common-sequence-operations).

**Неизменяемость.** Запись `s[0] = "К"` невозможна: элемент строки нельзя заменить на месте. Сложение `+` и повторение `*` создают строковый результат; связывание `s = s + "!"` меняет только имя `s`. Для определения результата не следует опираться на `id()`: повторное использование памяти или внутренние оптимизации не являются контрактом языка. Даже когда метод может вернуть уже существующий объект, гарантируется содержимое и неизменяемость, а не его идентичность. Модель объектов дана ранее в S02-M05. [Источник: Text Sequence Type — str](https://docs.python.org/3.14/library/stdtypes.html#text-sequence-type-str).

**Исполняемый пример P01.**

```python
text = "Кот"
print(len(text))
print(text[0], text[-1])
print("о" in text)

decomposed = "e\u0301"
print(len(decomposed))
print(decomposed[0] == "e")
print(decomposed[1] == "\u0301")

empty = ""
print(bool(empty))
```

Ожидаемый вывод:

```text
3
К т
True
2
True
True
False
```

**Разбор.** В `"Кот"` три кодовые точки; нулевая — `"К"`, последняя — `"т"`. `in` ищет подстроку. `"e\u0301"` состоит из латинской `e` и комбинируемого акцента `U+0301`; отображение зависит от среды, а длина остаётся 2. `bool("")` ложно по общему правилу истинности пустой последовательности. В примере не сравнивается картинка на экране, поэтому вывод воспроизводим без привязки к шрифту.

**Типичная ошибка:** `text[len(text)]`. Последний допустимый положительный индекс равен `len(text) - 1`, если строка не пуста. Альтернатива для последнего элемента — `text[-1]` с той же проверкой на пустоту.

### S02-M06-T003-P02 — Срезы строк

**Результат подтемы:** для `s[start:stop:step]` назвать выбранные индексы и результат, включая пропущенные границы, отрицательный шаг, пустую строку и нулевой шаг.

**Что и зачем.** Срез `s[start:stop:step]` возвращает строку из выбранных элементов. `start` — начальная позиция, `stop` — граница, **не включаемая** в результат, `step` — шаг. Для обычного положительного шага это позволяет брать префикс `s[:k]`, суффикс `s[k:]` и фрагмент `s[a:b]`. Длина `s[a:b]` при `0 <= a <= b <= len(s)` равна `b - a`. Поэтому соседние части `s[:k]` и `s[k:]` точно состыковываются: `s[:k] + s[k:] == s` для допустимого `k`.

Если шаг не указан, он равен 1. Если `start`/`stop` пропущены, Python выбирает границы в направлении шага. При положительном шаге это начало и конец строки. При отрицательном шаге направление меняется: `s[::-1]` даёт обратный порядок кодовых точек. Это не универсальное «переворачивание видимых символов»: комбинируемые знаки и составные эмодзи могут разрушиться визуально.

Для отрицательного шага удобно читать правило так: взять элемент на позиции `start`, затем идти к меньшим индексам, пока позиция не достигнет исключённой границы `stop`. В `s[4:1:-1]` выбраны индексы 4, 3, 2. Пропущенная конечная граница при отрицательном шаге означает «пройти до начала», и это **не то же самое**, что явно указать `-1`: явно заданный отрицательный индекс сначала трактуется относительно конца строки. `s[::-1]` и `s[:-1:-1]` поэтому дают разные результаты.

Срезы ведут себя мягче прямой индексации: границы вне диапазона обычно ограничиваются допустимым диапазоном, а направление, которое не позволяет выбрать элемент, даёт пустую строку. Нулевой шаг всегда `ValueError`. Параметры должны быть целыми индексами или `None`; дробное число не является допустимой границей. [Источники: Slicings](https://docs.python.org/3.14/reference/expressions.html#slicings), [Common Sequence Operations](https://docs.python.org/3.14/library/stdtypes.html#common-sequence-operations).

**Исполняемый пример P02.**

```python
s = "abcdef"
print(s[1:4])
print(s[:3] + s[3:])
print(s[::2])
print(s[4:1:-1])
print(s[::-1])
print(repr(s[:-1:-1]))
print(repr(s[100:]))
print(repr(s[2:2]))

try:
    print(s[::0])
except ValueError as error:
    print(type(error).__name__)
```

Ожидаемый вывод:

```text
bcd
abcdef
ace
edc
fedcba
''
''
''
ValueError
```

**Разбор.** `s[1:4]` берёт позиции 1, 2, 3. `s[::2]` — 0, 2, 4. `s[4:1:-1]` — 4, 3, 2. `repr()` здесь показывает пустую строку вместе с кавычками, чтобы пустой вывод был заметен. `try/except` в последней части — минимальная локальная форма «попытаться выполнить, при ошибке вывести её тип»; систематическое изучение исключений будет позже. Если этот синтаксис ещё не знаком, достаточно запустить строки выше и знать, что `s[::0]` сам по себе завершится `ValueError`.

**Сравнение с индексом.** `s[100]` вызовет `IndexError`; `s[100:]` вернёт пустую строку. Срез «скопировать последовательность выбранных элементов» и индекс «получить один обязательный элемент» имеют разные контракты. Срезы не изменяют исходную строку.

### S02-M06-T004-P01 — Поиск и преобразование

**Результат подтемы:** выбрать между `in`, `find()`, `count()` и строковыми преобразованиями по условию; предсказать результат, сохраняя в рассуждении неизменность исходной строки.

**Что и зачем.** В обработке текста часто надо узнать, есть ли подстрока, где она начинается, сколько раз встречается, или получить преобразованную версию. Метод вызывается у строки: `text.find("x")`. Ни один из методов этого раздела не меняет исходный `str`.

| Требование | Средство | Результат |
| --- | --- | --- |
| Проверить наличие | `sub in text` | `bool`. |
| Узнать первую позицию | `text.find(sub)` | Индекс или `-1`. |
| Посчитать неперекрывающиеся вхождения | `text.count(sub)` | Целое число. |
| Заменить подстроку | `text.replace(old, new)` | Строка с заменами. |
| Привести регистр | `text.lower()`, `text.upper()` | Преобразованная строка. |
| Убрать символы с краёв | `text.strip()` | Строка без краевых пробельных символов. |

`find()` возвращает `-1` при отсутствии подстроки. Это **не** отрицательный индекс найденного фрагмента. Если нужна лишь проверка наличия, читаемее `in`. Существующий соседний метод `index()` при ненахождении вызывает `ValueError`; выбирайте его, когда отсутствие — ошибка контракта, но полный разбор исключений будет позже. Параметры `start` и `end` у поиска ограничивают область поиска по тем же границам, что срез. [Источник: String Methods](https://docs.python.org/3.14/library/stdtypes.html#string-methods).

`count()` считает неперекрывающиеся вхождения. Поэтому `"aaaa".count("aa")` равно 2, а не 3: учитываются пары на позициях 0–1 и 2–3. Пустая подстрока — особый граничный случай: `"abc".count("")` равно 4, то есть число промежутков до, между и после трёх элементов. Пустая подстрока также содержится в любой строке: `"" in "abc"` истинно. Пустота здесь математически полезна для единообразия операций, но в прикладной задаче часто требует отдельной проверки входа. [Источник: str.count](https://docs.python.org/3.14/library/stdtypes.html#str.count).

`replace(old, new, count=-1)` ищет точное текстовое совпадение и возвращает результат. Необязательный третий аргумент ограничивает число замен. Он не меняет строку по имени `text`. Для замены **отдельных символов** или более сложных шаблонов существуют другие средства, но они вне этой подтемы. Простая строковая замена не понимает «слова» или грамматику.

`lower()` и `upper()` применяют правила регистра Unicode; преобразование может поменять число кодовых точек, поэтому нельзя обещать сохранение длины. Например, в Python 3.14 `"ß".upper() == "SS"`. Это операции изменения регистра, а не универсальная нормализация для человеческого поиска. Равенство визуально похожих текстов требует отдельных правил. Более подходящая операция для нечувствительного к регистру сравнения — `casefold()`, но и она сама по себе не выполняет Unicode-нормализацию; подробная международная обработка текста выходит за рамки модуля. [Источник: str.lower/upper/casefold](https://docs.python.org/3.14/library/stdtypes.html#string-methods).

`strip()` без аргумента удаляет пробельные символы (whitespace) **только с обоих краёв**. `strip(chars)` рассматривает переданную строку как **набор отдельных символов**, а не как готовый префикс или суффикс. Если требуется удалить ровно указанный префикс или суффикс, есть `removeprefix()` и `removesuffix()`. [Источник: str.strip](https://docs.python.org/3.14/library/stdtypes.html#str.strip).

**Исполняемый пример P01.**

```python
text = "  АБА-БА  "
print("БА" in text)
print(text.find("БА"))
print(text.find("нет"))
print("aaaa".count("aa"))
print("abc".count(""))

clean = text.strip()
print(repr(clean))
print(clean.replace("А", "а", 2))
print(repr(text))
print("ß".upper())
print("ПРИВЕТ".lower())
print("ababa".strip("ab"))
print("ababa".removeprefix("ab"))
```

Ожидаемый вывод:

```text
True
3
-1
2
4
'АБА-БА'
аБа-БА
'  АБА-БА  '
SS
привет

aba
```

**Разбор.** В `text` первые две позиции — пробелы; последовательность `"БА"` впервые начинается на позиции 3, внутри `"АБА"`. Следующее вхождение начинается на позиции 6. `strip()` создаёт значение без крайних пробелов, которое связывается с `clean`; `text` остаётся прежней. `replace(..., 2)` заменяет первые два вхождения `"А"`. `strip("ab")` снимает все подходящие краевые символы, поэтому его результат пуст и `print` даёт пустую строку. `removeprefix("ab")` удаляет только один точный префикс и даёт `"aba"`.

**Типичные ошибки:** проверять `if text.find(sub):` (позиция 0 ложна, `-1` истинна); ожидать изменения `text` после `text.replace(...)` без присваивания; использовать `strip("prefix")` для удаления целого префикса; считать `lower()` гарантией «побайтного» равенства похожих строк.

### S02-M06-T004-P02 — Разделение и форматирование

**Результат подтемы:** предсказать результат `split()` для режима по умолчанию и явного разделителя, собрать строковые части через `join()` и прочитать простую форматную спецификацию f-строки.

**Разделение.** `text.split(sep)` возвращает список фрагментов. Если разделитель `sep` задан, он ищется как точная подстрока. Соседние разделители дают пустые фрагменты; в начале и в конце строки они тоже возможны. Пустой разделитель `""` запрещён: Python вызывает `ValueError`, поскольку между кодовыми точками можно выделить разные неоднозначные границы. `maxsplit` ограничивает число разрезов, остаток остаётся целым фрагментом.

Когда `sep` опущен или равен `None`, поведение другое: подряд идущие пробельные символы считаются одним разделителем, крайние пустые фрагменты не появляются. `"".split()` даёт пустой список, тогда как `"".split(",")` даёт список из одной пустой строки. Это важно при чтении строк ввода. [Источник: str.split](https://docs.python.org/3.14/library/stdtypes.html#str.split).

**Сборка.** `separator.join(parts)` соединяет строки из `parts` и вставляет `separator` **между** соседними элементами, но не перед первым и не после последнего. Вызывается именно у разделителя: `", ".join(["a", "b"])`. Все элементы должны быть строками; числовой элемент нужно предварительно преобразовать `str(number)`. Для пустого списка результат — пустая строка, для одного элемента — сам текст без разделителя. Здесь список используется лишь как результат `split()` или явно заданная последовательность; его полная теория в S02-M07. [Источник: str.join](https://docs.python.org/3.14/library/stdtypes.html#str.join).

**Форматирование.** F-строка (formatted string literal, f-string) — строковый литерал с префиксом `f`. Выражения внутри `{...}` вычисляются во время выполнения, а их результаты превращаются в текст. Например, `f"{name}: {score}"`. Чтобы вывести фигурную скобку как текст, удвойте её: `f"{{{name}}}"`. После двоеточия в поле можно дать простую спецификацию формата: `{ratio:.2f}` означает форматировать число с двумя знаками после десятичной точки; `{number:04d}` — целое число с минимальной шириной 4 и нулевым дополнением. Форматирование меняет представление в строке, а не само числовое значение. [Источники: f-strings](https://docs.python.org/3.14/reference/lexical_analysis.html#f-strings), [Format Specification Mini-Language](https://docs.python.org/3.14/library/string.html#format-specification-mini-language).

Простая альтернатива — `str(value)`, если нужно лишь человекочитаемое представление одного значения. `repr(value)` показывает более диагностическое представление, например кавычки и экранированные символы строк; оно не обязано быть кодом, который можно снова исполнить. `str.format()` тоже форматирует по шаблону; здесь достаточно знать, что f-строка удобна при заранее известном шаблоне. F-строка не защищает автоматически данные в SQL, HTML или командах терминала: это просто построение текста. Такие контексты изучаются в соответствующих специальных курсах.

**Исполняемый пример P02.**

```python
print("  один\tдва  ".split())
print("один,,три,".split(","))
print("a:b:c".split(":", maxsplit=1))
print("".split())
print("".split(","))

parts = ["один", "два", "три"]
print(" | ".join(parts))
print("".join(parts))

name = "Ира"
score = 7
ratio = 2 / 3
print(f"Имя: {name}; балл: {score:04d}; доля: {ratio:.2f}")
print(f"{{{name}}}")
print(repr("a\nb"))
```

Ожидаемый вывод:

```text
['один', 'два']
['один', '', 'три', '']
['a', 'b:c']
[]
['']
один | два | три
одиндватри
Имя: Ира; балл: 0007; доля: 0.67
{Ира}
'a\nb'
```

**Разбор.** Первый `split()` схлопывает пробелы и табуляцию. Второй сохраняет пустые поля между запятыми и после последней запятой. Третий делает один разрез. `join()` помещает разделитель только между тремя значениями. `score:04d` добавляет нули слева; `ratio:.2f` округляет только отображение. `repr("a\nb")` печатает запись с видимым `\n` вместо настоящего переноса строки. Для диагностики вывода это удобнее, чем `print("a\nb")`.

**Типичные ошибки:** писать `parts.join(",")`; думать, что `split()` и `split(" ")` одинаковы; забывать пустое поле после конечного разделителя; складывать строку и число через `+` без явного преобразования; считать f-строку шаблоном, который обновится при последующем изменении переменной. F-строка вычисляется при каждом исполнении соответствующего выражения.

### S02-M06-T004-P03 — Текст и байты

**Результат подтемы:** для заданных текстовых и байтовых данных назвать тип и размер, выбрать направление `encode()`/`decode()` с явной кодировкой и объяснить возможную Unicode-ошибку.

**Что и зачем.** Текст описывает символы, а двоичный формат — числа от 0 до 255. `str` и `bytes` — разные типы, хотя оба допускают `len()` и индексацию. Кодирование `text.encode("utf-8")` создаёт байты из текста. Декодирование `data.decode("utf-8")` создаёт текст из байтов. У отправителя и получателя должна совпадать договорённость о кодировке. [Источники: Unicode HOWTO](https://docs.python.org/3.14/howto/unicode.html#encodings), [str.encode](https://docs.python.org/3.14/library/stdtypes.html#str.encode), [bytes.decode](https://docs.python.org/3.14/library/stdtypes.html#bytes.decode).

UTF-8 кодирует одну кодовую точку одним, двумя, тремя или четырьмя байтами. Например, латинская `A` занимает один байт, кириллическая `Я` — два, `😀` — четыре. Поэтому `len(text)` и `len(text.encode("utf-8"))` могут различаться. `bytes` при индексации возвращает **целое число**, а `str` — строку длины один. Запись `b"ABC"` — байтовый литерал; в непосредственном содержимом такого литерала допустимы ASCII-символы, а другие байты записывают escape-последовательностями. Не пытайтесь записывать `b"Я"` как прямой не-ASCII байтовый литерал.

По умолчанию `encode()` использует UTF-8; `decode()` также использует UTF-8. Для учебных примеров кодировку всё равно пишем явно, чтобы контракт был виден. Если текст нельзя представить выбранной кодировкой, возможно `UnicodeEncodeError`; если последовательность байтов не соответствует выбранной кодировке, `UnicodeDecodeError`. Оба класса относятся к семейству `UnicodeError`. Параметр `errors` позволяет заменить или игнорировать ошибочные данные, но это может потерять информацию; для сохранения точности обычен режим `strict` по умолчанию. Подробный выбор политики обработки ошибочных данных изучается вместе с файловым вводом-выводом в S04-M17. [Источник: codecs и error handlers](https://docs.python.org/3.14/library/codecs.html#error-handlers).

Нельзя «декодировать строку» методом `decode()`: она уже текст. Нельзя «кодировать байты» методом `encode()`: это уже байты. `str(data)` не равно декодированию: оно создаёт текстовое представление объекта байтов, например `"b'ABC'"`. Конкатенация `str` и `bytes` без явного выбора кодировки недопустима. Отдельная кодировка исходного файла `.py` (по умолчанию UTF-8) определяет, как парсер читает *саму программу*; она не диктует автоматически кодировку всех внешних данных. [Источник: Lexical Analysis](https://docs.python.org/3.14/reference/lexical_analysis.html#encoding-declarations).

**Исполняемый пример P03.**

```python
text = "AЯ😀"
data = text.encode("utf-8")
print(len(text))
print(len(data))
print(data)
print(data[0])
print(text[0])
print(data.decode("utf-8") == text)
print(str(b"ABC"))
print(b"ABC".decode("utf-8"))

try:
    b"\xff".decode("utf-8")
except UnicodeDecodeError as error:
    print(type(error).__name__)

try:
    "Я".encode("ascii")
except UnicodeEncodeError as error:
    print(type(error).__name__)
```

Ожидаемый вывод:

```text
3
7
b'A\xd0\xaf\xf0\x9f\x98\x80'
65
A
True
b'ABC'
ABC
UnicodeDecodeError
UnicodeEncodeError
```

**Разбор.** В `text` три кодовые точки. UTF-8 даёт 1 + 2 + 4 = 7 байтов. `data[0]` — число 65, код байта `A`; `text[0]` — строка `"A"`. `decode("utf-8")` восстанавливает исходный текст из корректно кодированных данных. `str(b"ABC")` выводит представление байтов с префиксом `b`, тогда как `decode` даёт `"ABC"`. Байта `0xFF` недостаточно для корректной UTF-8 последовательности; ASCII не может представить `Я`.

**Ограничение.** Срез байтов `data[1:2]` может отрезать часть многобайтового UTF-8 символа. После такого разреза декодирование может не удаться. Если задача о символах, индексируйте текст **после** декодирования; если задача о протоколе или файле на уровне байтов, работайте с `bytes` и явно учитывайте границы кодировки.

## 6. Как работают механизмы: пошаговая модель

Следующие шаги описывают **наблюдаемую семантику Python 3.14**. Они не утверждают конкретный порядок машинных инструкций, структуру памяти или алгоритм поиска внутри каждого интерпретатора.

### От текстового литерала к элементам строки

1. При чтении файла `.py` интерпретатор сначала декодирует текст исходного кода в соответствии с кодировкой файла (по умолчанию UTF-8). Это относится к **файлу программы**, а не к данным, которые программа позже получит от пользователя.
2. Запись литерала, например `"A\n"`, разбирается по правилам языка. Escape-последовательность `\n` в обычном литерале обозначает одну кодовую точку перевода строки; два символа исходного текста `\` и `n` не остаются двумя элементами значения. В `r"A\n"` префикс raw меняет обработку большинства escape-последовательностей: полученная строка содержит обратную косую черту и `n`. Raw-строки полезны, когда важны буквальные обратные косые черты, но у них есть синтаксические ограничения; например, литерал не может завершаться одиночной необработанной обратной косой чертой. [Источник: String and Bytes Literals](https://docs.python.org/3.14/reference/lexical_analysis.html#string-and-bytes-literals).
3. Во время выполнения значение `str` доступно как последовательность кодовых точек. `len()`, индексация и `for` работают с элементами этой последовательности. Если визуальное отображение объединяет элементы, правило Python не меняется.
4. Метод получает строковое значение и аргументы. Его контракт определяет возвращаемое значение или ошибку. Поскольку `str` неизменяем, метод не может поменять её содержимое. После `s = s.replace("x", "y")` имя `s` связывается с результатом; любые другие имена, связанные со старым значением, сохраняют старый текст.

### Индекс и срез

1. Для индекса `i` Python определяет одну позицию: при отрицательном `i` её мысленно можно пересчитать как `len(s) + i`.
2. Если такая позиция отсутствует, `s[i]` вызывает `IndexError`.
3. Для среза Python получает до трёх границ. При пропуске границы выбирается значение, соответствующее направлению шага.
4. Затем выбираются позиции с данным шагом, до исключённого `stop`. Пустой набор позиций даёт пустую строку. `step == 0` недопустим и вызывает `ValueError`.
5. Результат среза — значение типа `str`. Не следует делать вывод о том, был ли физически создан отдельный объект, по одному сравнению `is` или одному значению `id()`: это не часть контракта среза.

Наглядная таблица для `s = "abcde"`:

| Выражение | Выбранные индексы | Значение |
| --- | --- | --- |
| `s[1:4]` | 1, 2, 3 | `"bcd"` |
| `s[:2]` | 0, 1 | `"ab"` |
| `s[::2]` | 0, 2, 4 | `"ace"` |
| `s[4:1:-1]` | 4, 3, 2 | `"edc"` |
| `s[2:2]` | нет | `""` |

### От текста к байтам и обратно

1. Выбирается кодировка — правило, общее для отправителя и получателя. В примерах это UTF-8.
2. Кодировщик проходит по кодовым точкам текста и выдаёт последовательность байтов. Результат имеет тип `bytes`. Один элемент текста может дать несколько байтов.
3. Декодировщик читает байты по правилам той же кодировки и восстанавливает кодовые точки. Если байтовая последовательность некорректна или правила не совпали, возможна ошибка либо неверный текст, в зависимости от входа и выбранной политики ошибок.
4. Для корректного текста, представимого выбранной кодировкой, `text.encode(enc).decode(enc) == text`. Это равенство значений, не обещание идентичности объектов. Оно предполагает одинаковую кодировку и режим обработки без потери данных.

### Стоимость операций

Пусть `n` — число кодовых точек исходной строки, `k` — число кодовых точек результата, а `m` — длина искомой подстроки. `len(s)` и доступ к одному элементу удобно считать `O(1)` в обычной модели Python/CPython. Создание строки из `k` выбранных элементов требует места для результата, то есть в обычной модели не меньше `O(k)` дополнительного пространства. Проход `for` по всей строке требует `O(n)` шагов. Вызов `find()`, `replace()` или `split()` по большому тексту не надо объявлять `O(1)`: им нужно исследовать вход и/или создать выход. Точная верхняя оценка поиска зависит от алгоритма реализации и свойств входа; здесь достаточно понимать линейный проход как учебную базовую модель, а не обещать универсальное `O(n)` для любого метода и реализации.

Накопление текста через `result = result + piece` в цикле может многократно копировать уже построенный префикс и приводить к квадратичному общему объёму работы при последовательном добавлении коротких частей. `join()` выражает задачу сборки явно и обычно предпочтителен, когда части уже есть. Это практическая рекомендация, **не** гарантия одинакового ускорения для каждого запуска: CPython может оптимизировать отдельные случаи конкатенации. При оценке следует назвать модель и не выводить сложность из одного замера. [Источники: Immutable Sequence Types](https://docs.python.org/3.14/library/stdtypes.html#immutable-sequence-types), [str.join](https://docs.python.org/3.14/library/stdtypes.html#str.join).

## 7. Сравнение похожих механизмов

| Пара | Главное различие | Когда выбирать |
| --- | --- | --- |
| `s[i]` / `s[a:b]` | Индекс требует один существующий элемент; срез выбирает диапазон и может быть пустым. | Отдельная позиция / фрагмент. |
| `len(s)` / `len(s.encode("utf-8"))` | Кодовые точки / байты кодировки. | Логика текста / размер передаваемых данных. |
| `sub in s` / `s.find(sub)` | Ответ да/нет / начальная позиция или `-1`. | Проверить наличие / использовать позицию. |
| `s.find(sub)` / `s.index(sub)` | `-1` при отсутствии / `ValueError` при отсутствии. | Отсутствие допустимо / отсутствие нарушает ожидание. |
| `s.strip(chars)` / `s.removeprefix(prefix)` | Удаление множества символов с краёв / одного точного префикса. | Очистка краёв / удаление известной метки. |
| `s.split()` / `s.split(" ")` | Группы любых пробельных символов, без пустых крайних полей / точный пробел с сохранением пустых полей. | Слова в свободном тексте / формат с явным разделителем. |
| `str(value)` / `repr(value)` | Представление для человека / диагностическое представление. | Вывод пользователю / разбор значения. |
| `str(data)` / `data.decode("utf-8")` | Текстовое представление объекта `bytes` / восстановление текста из байтов. | Диагностика байтов / чтение закодированного текста. |
| `==` / `is` для строк | Равенство содержимого / идентичность объектов. | Сравнение текста / редкие случаи анализа объектов. |

## 8. Дополнительный исполняемый пример

Один небольшой проход показывает, как применять операции вместе. Это **пример**, не задача для самостоятельного решения.

```python
source = "  красный; синий; зелёный  "
clean = source.strip()
parts = clean.split("; ")
result = " / ".join(parts)

print(repr(source))
print(repr(clean))
print(parts)
print(result)
print(len(result))
print(len(result.encode("utf-8")))
```

Ожидаемый вывод:

```text
'  красный; синий; зелёный  '
'красный; синий; зелёный'
['красный', 'синий', 'зелёный']
красный / синий / зелёный
25
44
```

## 9. Подробный разбор примера

`source` содержит по два крайних пробела. `strip()` даёт `clean` без них, но `source` не изменяется, что видно из `repr(source)`. `split("; ")` ищет строго два элемента: точку с запятой и пробел. Полученный список содержит три строки. `" / ".join(parts)` вставляет трёхсимвольный разделитель между соседними частями. В `result` 25 кодовых точек: 7 в `красный`, 5 в `синий`, 7 в `зелёный` и по 3 в каждом из двух разделителей, то есть 7 + 3 + 5 + 3 + 7 = 25. Все 19 кириллических букв занимают по два байта UTF-8; шесть ASCII-символов разделителей занимают по одному, поэтому всего 44 байта. Если формат входа допускает разные пробелы вокруг `;`, этот простой `split("; ")` его не обработает одинаково: контракт разделителя здесь точный.

## 10. Типичные ошибки начинающих

1. **Смешивать индекс и длину.** В строке длины `n` последний положительный индекс `n - 1`. Для `n = 0` такого индекса нет.
2. **Считать срез включающим `stop`.** `s[1:3]` выбирает позиции 1 и 2; граница 3 исключена.
3. **Считать `len()` числом видимых знаков или байтов.** Это число кодовых точек `str`. Для байтовой длины нужен результат кодирования.
4. **Пытаться изменить строку через индекс.** `s[0] = "x"` вызывает `TypeError`; создавайте результат и привязывайте имя.
5. **Игнорировать возвращённое значение метода.** `s.strip()` само по себе не перепривязывает `s`.
6. **Писать `if s.find(sub):`.** Индекс 0 ложен, а `-1` истинен; используйте `sub in s` или явное сравнение с `-1`.
7. **Считать `strip(chars)` удалением точного фрагмента.** Этот аргумент задаёт набор символов; используйте `removeprefix()`/`removesuffix()` для точной метки.
8. **Путать два режима `split()`.** Без аргумента последовательности пробелов объединяются, с явным разделителем пустые поля сохраняются.
9. **Вызывать `join()` у списка.** Разделитель — строковый объект, на котором вызывают метод.
10. **Путать текст и его кодировку.** Unicode описывает кодовые точки, UTF-8 — способ превратить их в байты.
11. **Принимать `str(bytes)` за декодирование.** Это представление объекта, а не восстановление исходного текста.
12. **Сравнивать строки через `is`.** Результат может зависеть от деталей хранения; для текста нужен `==`.

## 11. Неочевидные случаи и ограничения

- Пустая подстрока присутствует даже в пустой строке: `"" in ""` истинно. `"abc".find("")` равно 0, а `"abc".count("")` равно 4. Проверяйте пустой запрос отдельно, если он не имеет смысла в вашей задаче.
- `"a" * 0` и `"a" * -1` дают пустую строку. Отрицательное повторение не означает обратную строку.
- `s[::-1]` переставляет кодовые точки, поэтому может отделить комбинируемый знак от базовой буквы. Для пользовательских видимых знаков нужна отдельная сегментация.
- Два текста могут выглядеть одинаково, но не быть равными: `"\u00e9"` содержит одну кодовую точку, а `"e\u0301"` — две. `==` сравнивает последовательности кодовых точек, а не внешний вид. Unicode-нормализация — отдельная операция, не выполняемая автоматически строковым равенством. [Источник: Unicode HOWTO](https://docs.python.org/3.14/howto/unicode.html#comparing-strings).
- `upper()` и `lower()` не обязаны сохранять длину и не дают полноценных правил сравнения на всех языках.
- Форматная ширина в f-строке не равна гарантированной ширине в экранных колонках: шрифты, комбинируемые знаки и широкие символы отображаются по-разному.
- `bytes` может содержать нулевой байт `0x00`; это обычный элемент последовательности. Байтовый `len()` считает его. Утверждения о нуль-терминированных C-строках не следует переносить на контракт Python `bytes` или `str`.
- Параметр `errors="ignore"` при декодировании может молча удалить байты, поэтому успешное выполнение не обязательно означает сохранение исходной информации.

## 12. Что относится к CPython 3.14

**Язык Python:** доступ к `str` по индексам, поведение срезов, неизменяемость, значения методов, кодирование и декодирование определяются публичным контрактом Python 3.14 и его стандартной библиотеки. Эти правила не требуют знания конкретной внутренней структуры CPython.

**Реализация CPython 3.14:** Unicode-объекты используют гибкое внутреннее представление (flexible string representation, PEP 393). Для разных диапазонов кодовых точек возможны разные представления; CPython не обязан хранить каждую строку как UTF-8. При необходимости UTF-8 представление может создаваться и кэшироваться внутри объекта. Это объясняет, почему неверно говорить «Python-строка — массив UTF-8 байтов». Внутренний буфер CPython содержит дополнительный завершающий нулевой элемент для совместимости с C API, но он не входит в `len()`. Эти детали **не** являются переносимым контрактом языка и не нужны для выбора `encode()`/`decode()`. [Источник: Unicode Objects and Codecs, CPython C API](https://docs.python.org/3.14/c-api/unicode.html#unicode-objects); [PEP 393](https://peps.python.org/pep-0393/).

CPython может использовать интернирование (interning) и другие оптимизации строк. Поэтому `a is b` для равных строк иногда даёт `True`, иногда `False` в зависимости от способа создания значений и реализации. Для проверки равенства содержимого используйте `==`. Нельзя выводить гарантию языка из результата `id()`, одного замера памяти или конкретного байткода. Подробное устройство памяти будет повторено в S06-M23.

## 15. Итоговый конспект

Строка в Python 3.14 — неизменяемая последовательность кодовых точек Unicode. Индекс берёт один элемент и может вызвать `IndexError`; срез выбирает диапазон с исключённой правой границей и может быть пустым. `len()` считает элементы строки, а не байты и не видимые знаки.

Строковые методы возвращают значения. Для наличия подстроки используйте `in`, для позиции — `find()` с проверкой `-1`. `strip(chars)` удаляет отдельные краевые символы из заданного набора. `split()` без аргумента и с явным разделителем имеют разные правила. `join()` собирает строки с разделителем. F-строка превращает вычисленные значения в нужное текстовое представление.

`str` — текст; `bytes` — данные из байтов. `encode()` переводит текст в байты, `decode()` делает обратное. UTF-8 — кодировка, а не синоним Unicode. Гибкое представление текста в CPython 3.14 — деталь реализации, не правило языка.
