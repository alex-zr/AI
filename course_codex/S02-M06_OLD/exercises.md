## Как работать с заданиями

Задания идут от прямого применения одного приёма к комбинированию и переносу. Для каждой задачи указаны тестовые примеры с ожидаемым результатом; они являются частью контракта, но не исчерпывают проверок. Время `O(n)` считается по числу кодовых точек строки или числу байтов, явно указанному в задаче. Дополнительная память не включает вход и возвращаемое значение, если задача отдельно не говорит иначе. Точная скорость встроенных операций может зависеть от реализации; ожидаемые оценки описывают учебную модель обработки входа.

**Точки появления:** слайды `S02-M06` ещё не подготовлены. Поэтому каждая точка названа по содержимому блока, который должен ей предшествовать; при создании `slides_plan.md` эти точки нужно связать с фактическими ID слайдов. Порядок по подтемам сохраняется: после каждой подтемы есть хотя бы одна простая задача. Поздние категории не вставляются до появления нужных объяснений.

### S02-M06-E01 — Крайние знаки строки

- **Подтема и результат:** `S02-M06-T003-P01`; извлекать крайние элементы строки и объяснять поведение пустой строки.
- **Категория / сложность:** простая / простая.
- **Появление:** после слайдового блока про `len()`, положительный и отрицательный индексы, пустую строку и проверку `if text:`.
- **Контекст:** панель статуса показывает размер короткой метки и её первый и последний элементы.
- **Условие:** напишите функцию `edge_report(text)`. Для непустой строки верните строку формата `длина|первый|последний`, например `3|К|т`. Для пустой строки верните `0|<пусто>|<пусто>`. Используйте `len()` и индексацию; не считайте видимые глифы.
- **Вход:** один объект типа `str`.
- **Ожидаемый результат:** строка установленного формата; исходный текст не меняется.
- **Ограничения:** длина входа от 0 до 100 кодовых точек; формат разделителей точный.
- **Обычные случаи:** `edge_report("Кот") == "3|К|т"`; `edge_report("x") == "1|x|x"`.
- **Граничные случаи:** `edge_report("") == "0|<пусто>|<пусто>"`; `edge_report("e\u0301") == "2|e|\u0301"`.
- **Критерии проверки:** корректные длина и индексы; пустая строка обрабатывается без `IndexError`; формат точный; длина для комбинируемого примера считается по кодовым точкам.
- **Ожидаемая сложность:** время `O(1)` после получения длины в стандартной учебной модели строк; дополнительная память `O(1)` без учёта возвращаемой строки. Построение результата включает постоянное число частей.

- **Контекст:** компактная карточка показывает код заявки с ведущими нулями и долю с двумя знаками после точки.
- **Условие:** сформируйте строку `Код: 0007; доля: 0.67` из `code = 7` и `ratio = 2 / 3`, используя одну f-строку. После форматирования проверьте отдельной печатью, что `ratio` по-прежнему числовое значение, а не полученная строка.
- **Вход:** `code` — целое число от 0 до 9999; `ratio` — конечное вещественное число.
- **Ожидаемый результат:** подпись с минимальной шириной кода 4 и двумя знаками после десятичной точки; `ratio` не переназначается.
- **Ограничения:** формат результата должен совпадать с образцом; не округлять и не заменять исходное число вручную.
- **Обычные случаи:** `code=7, ratio=2/3` даёт `"Код: 0007; доля: 0.67"`; `code=42, ratio=1.0` даёт `"Код: 0042; доля: 1.00"`.
- **Граничные случаи:** `code=0` даёт `0000`; значение `ratio=0.0` отображается как `0.00`.
- **Критерии проверки:** применены спецификации `04d` и `.2f` (или эквивалентные); f-строка оценивается при выполнении; тип исходного `ratio` остаётся числовым.
- **Ожидаемая сложность:** время и дополнительная память `O(1)` относительно формата фиксированной длины.

### S02-M06-E12 — Разобрать список меток и объяснить контракт

- **Подтемы и результаты:** основная `S02-M06-T004-P02`; интеграция `S02-M06-T004-P01` и `S02-M06-T003-P02`. Отмеченная интеграция подтем обязательна для объяснения, но не изменяет плановый счёт: задача учитывается только в P02.
- **Категория / сложность:** интервью / средняя.
- **Появление:** после всех блоков про `split()`, `join()`, `strip()` и срезы; в слайдах до неё должны быть пояснены точный разделитель и включение/исключение полей.
- **Контекст:** небольшая телеметрия передаёт поля через `;`, а интерфейс должен показать только первые `k` меток.
- **Условие:** напишите `preview_tags(payload, k)`. Уточните у интервьюера (или зафиксируйте допущения): сохранять ли пустые поля, что делать при `k <= 0`, удалять ли пробелы вокруг полей. При отсутствии уточнений используйте следующий контракт: разрезать только по точной строке `";"`, сохранить пустые поля, убрать пробелы с краёв каждого поля, взять первые `max(k, 0)` полей и соединить их через `", "`. Не меняйте регистр. Объясните корректность порядка действий и оцените сложность.
- **Вход:** строка `payload`, целое `k`.
- **Ожидаемый результат:** строка с первыми выбранными полями, соединёнными через `", "`; при `k <= 0` результат `""`.
- **Ограничения:** `payload` до 100 000 кодовых точек; `k` может быть отрицательным или больше числа полей; поля не содержат экранированного `;`.
- **Обычные случаи:** `preview_tags("red; blue;green", 2) == "red, blue"`; `preview_tags("a;b", 5) == "a, b"`.
- **Граничные случаи:** `preview_tags("", 3) == ""`; `preview_tags(";x;", 3) == ", x, "`; `preview_tags("a;b", 0) == ""`.
- **Критерии проверки:** сначала названы неоднозначности и выбран контракт; точный разделитель и пустые поля обработаны верно; обрезаются края каждого поля, не весь payload; предел `k` соблюдён; устное объяснение называет число проходов и объём результата.
- **Ожидаемая сложность:** время `O(n)`; дополнительная память `O(n)` для списка полей и результата.
- **Устное объяснение:** кратко опишите контракт, затем объясните `split → обработка краёв → выбор первых k → join`; укажите, почему обработка кавычек/экранирования не поддерживается данным форматом; назовите `O(n)` времени и памяти.

### S02-M06-E13 — Кодировать подпись в UTF-8

- **Подтема и результат:** `S02-M06-T004-P03`; различать текст и байты, применять `encode()` и считать байты.
- **Категория / сложность:** простая / простая.
- **Появление:** после слайдового блока о направлении `str → bytes` и UTF-8.
- **Контекст:** перед отправкой короткой подписи сервис должен сообщить размер полезной нагрузки в байтах.
- **Условие:** для заданной строки получите UTF-8 байты, затем напечатайте их и их длину. Отдельно выведите длину исходного текста. Кодировку укажите явно.
- **Вход:** строка `"AЯ😀"`.
- **Ожидаемый результат:** байты `b'A\xd0\xaf\xf0\x9f\x98\x80'`, длина текста `3`, длина байтов `7`.
- **Ограничения:** использовать UTF-8; не выводить число байтов из визуального вида символов.
- **Обычные случаи:** ASCII-строка `"ABC"` имеет длину текста 3 и UTF-8 длину 3.
- **Граничные случаи:** пустая строка кодируется в `b''` длины 0; кириллица и эмодзи занимают более одного байта каждый.
- **Критерии проверки:** выбран тип `bytes`; кодировка указана явно; разделены `len(text)` и `len(data)`.
- **Ожидаемая сложность:** время `O(n)` по числу кодовых точек; дополнительная память `O(b)` по длине закодированного результата.

### S02-M06-E14 — Проверить повреждённую текстовую нагрузку

- **Подтемы и результаты:** основная `S02-M06-T004-P03`; интеграция `S02-M06-T004-P02` — сформировать понятную текстовую сводку. В плановом числе задача учитывается только в P03.
- **Категория / сложность:** интервью / средняя.
- **Появление:** после слайдового блока о `decode()`, UTF-8 и `UnicodeDecodeError`; f-строка используется только для краткой сводки уже разобранных значений.
- **Контекст:** диагностическая утилита получает байтовую нагрузку и обязана явно различать корректный UTF-8 и повреждённые данные.
- **Условие:** реализуйте `decode_report(data)`. Уточните, следует ли молча пропускать повреждённые байты, заменять их или сообщать об ошибке. Если спецификация не задаёт политику, выберите безопасный учебный контракт: декодировать UTF-8 в режиме `strict`; при успехе вернуть `OK:<текст>`, а при `UnicodeDecodeError` вернуть `ERROR:invalid UTF-8`. Входные байты не изменять. Объясните, почему `str(data)` не является декодированием.
- **Вход:** объект `bytes`.
- **Ожидаемый результат:** строка одного из двух форматов по контракту выше.
- **Ограничения:** размер до 100 000 байт; кодировка фиксирована UTF-8; наружу не выводить traceback и не использовать `errors="ignore"`.
- **Обычные случаи:** `decode_report("Привет".encode("utf-8")) == "OK:Привет"`; `decode_report(b"ABC") == "OK:ABC"`.
- **Граничные случаи:** `decode_report(b"") == "OK:"`; `decode_report(b"\xff") == "ERROR:invalid UTF-8"`; неполная последовательность UTF-8 также считается ошибкой.
- **Критерии проверки:** корректно выбрана политика после фиксации требования; выполняется именно `decode("utf-8")`; обработан только ожидаемый `UnicodeDecodeError`; исходные байты не переписываются; устно отделены текст от байтов и кодировка от Unicode.
- **Ожидаемая сложность:** время `O(b)` по числу входных байтов; дополнительная память `O(n)` при успешном декодировании для строки длины `n`, без учёта результата.
- **Устное объяснение:** назовите неоднозначности политики ошибок; объясните направление `bytes → str`; покажите разницу с `str(data)`; оцените время и дополнительную память.
