## Что именно проверяет автогрейдер

1. **Таблица `CASES`** содержит 260 независимо записанных ожиданий: обычные и граничные примеры из `exercises.md`, плюс несколько дополнительных случаев. Ожидания не вычисляются из `reference_solutions.py`.
2. **Оракулы** проверяют механизм, а не тот же код:
   - `E17` — сравнение с `text == text[::-1]`;
   - `E25` — исчерпывающая сверка с настоящим срезом для 8 строк, 12 границ и 7 шагов, включая `None` и `step=0`;
   - `E29` — сравнение с `str.count` для непустых подстрок;
   - `E31` — сравнение с `str.replace` для непустого `old`.
3. **Типы** проверяются отдельно: `bool` не принимается за `0/1`, `None` не принимается за `-1`, `int` не принимается за строку.
4. **Запреты** (`E17` — без `[::-1]`; `E25` — без среза, `slice()` и `range(start, stop, step)`; `E28` — без `in`/`find()`; `E29` — без `str.count`; `E31` — без `str.replace`; `E43` — без `decode()`/`str(data)`) проверяются вручную по исходнику. Автогрейдер намеренно не делает статический анализ: он принимает любую реализацию, которая даёт правильный результат.

## Подсказки с постепенным раскрытием

Выдавать только после самостоятельной попытки и фиксировать факт подсказки.

### `E19` — сдвиг букв

1. Сначала проверьте, что буква входит в `A`–`Z`; иначе верните её без изменений.
2. Для входа в диапазон вычтите код `A`, прибавьте сдвиг, возьмите остаток по модулю 26 и верните код обратно.
3. Нормализуйте `shift` один раз до цикла; это упрощает отрицательные и большие значения.

### `E25` — срез без среза

1. Разделите случаи `step > 0` и `step < 0`: у них разные значения по умолчанию и разные границы ограничения.
2. Для `step > 0` допустимый диапазон — `0..n`, для `step < 0` — `-1..n-1`; отрицательные `start`/`stop` сначала увеличиваются на `n`.
3. После ограничения границ используйте `while`: для положительного шага условие `i < stop`, для отрицательного — `i > stop`.
4. Не путайте пропущенный `stop` (граница перед началом) с явным `-1` (последний индекс).

### `E31` — ограниченная замена

1. Храните `start` — позицию, с которой продолжается поиск, и `replaced` — число уже сделанных замен.
2. На каждом шаге добавляйте `text[start:position]`, затем `new`, затем переносите `start` за `old`.
3. После цикла обязательно добавьте `text[start:]`, иначе потеряется хвост.
4. `limit < 0` означает «без ограничения»; `limit == 0` можно обработать отдельно.

### `E37` — нормализация записей

1. Сначала разбейте по `;` и пропустите пустые записи после `strip()`.
2. Ищите первое `:` через `find()`; позиция `-1` и позиция `0` обе нарушают контракт.
3. Ключ и значение проверяйте после `strip()`; значение может содержать `:`.
4. Собирайте результат с разделителем `" | "` только между непустыми записями.

### `E43` — ASCII-протокол

1. `bytes` индексируется в целые числа; `data[index]` уже не строка.
2. Проверяйте `value > 127` до `chr(value)`.
3. При первом нарушении сразу возвращайте `bad:<index>:<value>`.
4. Для корректных байтов собирайте текст через `chr(value)`; пустой вход даёт `ok:`.

### `E44` — бюджет сообщения

1. Идите по кодовым точкам, а не по байтам.
2. Для каждой кодовой точки считайте `len(ch.encode("utf-8"))` и проверяйте, помещается ли она в остаток лимита.
3. Остановитесь перед первой точкой, которая не помещается; не добавляйте её частично.
4. Префикс можно взять срезом `text[:count]` после цикла; это дешевле, чем накапливать строку через `+=`.
