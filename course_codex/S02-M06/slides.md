# Строка — последовательность позиций

**Цель:** научиться брать один элемент и объяснять, почему позиция допустима или нет.

**Интуитивная модель:** строка — ожерелье пронумерованных бусин.

```text
бусины:    К   о   т
индексы:   0   1   2
с конца:   -3  -2  -1
```

- Одна бусина — одна **кодовая точка** (code point) Unicode.
- `len(text)` — число бусин.
- `text[i]` — взять бусину с номером `i`.

**Важно:** число бусин не всегда равно числу видимых знаков. Это разберём на `SL005`.

<!-- S02-M06-SL004 -->
# Индекс: точное правило

**Гарантия языка Python 3.14.** Для строки `s` длины `n = len(s)`:

- допустимы индексы `0 … n-1` и `-n … -1`;
- отрицательный индекс пересчитывается как `n + i`;
- `s[i]` возвращает `str` длины 1;
- вне диапазона — `IndexError`.

```python
text = "Кот"
print(len(text))
print(text[0], text[-1])
print(text[-len(text)])
```

**Вывод:**

```text
3
К т
К
```

**Разбор:** `text[0]` — `"К"`, `text[-1]` — позиция `3 + (-1) = 2`, то есть `"т"`. `text[-3]` — позиция `0`.

<!-- Заметки докладчика: это семантика последовательностей Python 3.14. Для пустой строки допустимых индексов нет — граница разбирается на SL007. Теория: §5.1, «Как работает индексация». -->

<!-- S02-M06-SL005 -->
# Кодовая точка — не экранный знак

`len(str)` считает **кодовые точки**, а не байты и не графемные кластеры.

```python
text = "e\u0301"
print(len(text))
print(text[0] == "e", text[1] == "\u0301")
print(hex(ord("😀")))
print(len("😀"))
```

**Вывод:**

```text
2
True True
0x1f600
1
```

**Разбор:** `"e\u0301"` — латинская `e` плюс комбинируемый акут. Визуально это может выглядеть как `é`, но элементов два. `ord()` даёт числовой код точки, `chr()` выполняет обратное преобразование, `hex(n)` показывает число в шестнадцатеричной записи.

**Граница:** `==` не выполняет Unicode-нормализацию: `"e\u0301" != "\u00e9"`.

# Элемент — строка; строка неизменяема

Отдельного типа `char` в Python нет: `s[0]` — это `str` длины 1.

```python
s = "кот"
t = s
s = s + "!"
print(s)
print(t)
try:
    s[0] = "К"
except TypeError as error:
    print(type(error).__name__)
```

**Вывод:**

```text
кот!
кот
TypeError
```

**Разбор:** `+` создаёт новую строку, а `s = ...` перепривязывает только имя `s`. Имя `t` остаётся связано со старой строкой `"кот"`. Присваивание элементу невозможно: строковый объект неизменяем.

# Границы и сравнение

- Последний положительный индекс: `len(s) - 1`.
- `s[len(s)]` — уже за границей.
- У пустой строки индексов нет: сначала `if text:`.
- Для текста используйте `==`, не `is`: `is` проверяет идентичность объектов.

```python
text = "Кот"
try:
    text[len(text)]
except IndexError as error:
    print(type(error).__name__)
print("кот" == "Кот", "кот" is "Кот")
print(repr("кот"))
```

**Вывод:**

```text
IndexError
False False
'кот'
```

**Типичная ошибка:** `if text.find(...)` и `s[len(s)]` — разные ловушки, но обе связаны с неверной границей. Первую разберём в `SL029`.

**Диагностика:** `repr(text)` показывает строку с кавычками и escape-последовательностями; подробнее — на `SL040`.

# Срез — интервал с исключённой границей

**Цель:** получать фрагмент без цикла и точно называть выбранные позиции.


**Текстовая альтернатива схеме:** `s[1:4]` для `"abcdef"` выбирает индексы 1, 2, 3 и даёт `"bcd"`.

<!-- S02-M06-SL015 -->
# Точное правило среза

**Гарантия языка Python 3.14.** Выражение: `s[start:stop:step]`.

| Параметр | При `step > 0` | При `step < 0` |
| --- | --- | --- |
| `start` по умолчанию | `0` | `len(s) - 1` |
| `stop` по умолчанию | `len(s)` | граница перед началом |
| направление | слева направо | справа налево |

- `step == 0` — `ValueError`.
- Явные отрицательные границы пересчитываются от конца.
- Границы ограничиваются диапазоном: срез не даёт `IndexError` из-за выхода за край.
- Результат всегда `str`, возможно пустая.

# Срезы: исполняемый пример

```python
s = "abcdef"
print(s[1:4])
print(s[:3] + s[3:])
print(s[::2])
print(s[-4:-1])
```

**Вывод:**

```text
bcd
abcdef
ace
cde
```

**Разбор по индексам:**

- `s[1:4]` → 1, 2, 3 → `"bcd"`;
- `s[:3]` → 0, 1, 2; `s[3:]` → 3, 4, 5; вместе — вся строка;
- `s[::2]` → 0, 2, 4 → `"ace"`;
- `s[-4:-1]` → `s[2:5]` → 2, 3, 4 → `"cde"`.

<!-- S02-M06-SL017 -->
# Отрицательный шаг меняет всё

```python
s = "abcdef"
print(s[4:1:-1])
print(s[::-1])
print(repr(s[:-1:-1]))
print(repr(s[100:]))
```

**Вывод:**

```text
edc
fedcba
''
''
```

**Разбор:** при `step < 0` пропущенный `start` — последний индекс, пропущенный `stop` — граница перед началом. В `s[:-1:-1]` явный `stop = -1` пересчитывается в последний индекс; старт и стоп совпали, поэтому диапазон пуст.

**Следствие:** `s[::-1]` и `s[:-1:-1]` — разные выражения.

<!-- Заметки докладчика: это ключевая тонкость подтемы. Не говорить «-1 всегда значит до начала»: при отрицательном шаге явный -1 означает последний элемент. Теория: §5.2, «Значения по умолчанию». -->

# Границы, ошибки и стоимость

```python
s = "abcdef"
try:
    s[::0]
except ValueError as error:
    print(type(error).__name__)
print(repr(s[2:2]))
print(len(s[::-1]))
```

**Вывод:**

```text
ValueError
''
6
```

- `s[100]` может дать `IndexError`, а `s[100:]` — пустую строку.
- `s[2:2]` пуст: начало и конец совпали.
- Срез создаёт новую строку: время и память `O(k)`, где `k` — длина результата.

**Граница:** срез не нормализует Unicode и может разорвать графемный кластер.

# Наличие, позиция и ошибка

```python
text = "абракадабра"
print("бра" in text)
print(text.find("бра"))
print(text.find("нет"))

print(name.startswith("report"))

```

```text

1
-1
True
True
```

- `index()` возвращает позицию, но при отсутствии даёт `ValueError`.

# `split()`: два разных режима

**Цель:** разбирать текст на части и понимать, когда пустые поля являются частью результата.

| Вызов | Разделитель | Пустые поля |
| --- | --- | --- |
| `text.split()` | любая группа пробельных символов | крайние отбрасываются |
| `text.split(sep)` | точная подстрока `sep` | сохраняются |
| `text.split(sep, maxsplit)` | точная подстрока, не более `maxsplit` разрезов | остаток — одним фрагментом |

- `"".split()` → `[]`.
- `"".split(",")` → `['']`.
- `text.split("")` → `ValueError`.

<!-- Заметки докладчика: это разные контракты, а не «одно и то же с пробелом». Теория: §5.4, «Разделение». -->

<!-- S02-M06-SL037 -->
# Разделение: исполняемый пример

```python
print("  один\tдва  ".split())
print("один,,три,".split(","))
print("a:b:c".split(":", maxsplit=1))
print("a:b:c".rsplit(":", maxsplit=1))
```

**Вывод:**

```text
['один', 'два']
['один', '', 'три', '']
['a', 'b:c']
['a:b', 'c']
```

**Разбор:** без аргумента пробелы и табуляция схлопываются, края отбрасываются. С явным `","` пустые поля между запятыми и после последней запятой сохраняются. `maxsplit` ограничивает число разрезов: `split` режет слева, `rsplit` — справа.

# Текст и байты — разные типы

**Цель:** понять, где заканчивается текст и начинается его байтовое представление.

| Свойство | `str` | `bytes` |
| --- | --- | --- |
| Что хранит | кодовые точки Unicode | целые числа 0–255 |
| `data[i]` | `str` длины 1 | `int` |
| `len()` | кодовые точки | байты |
| Назначение | текстовая логика | файлы, сеть, протоколы |

```text
str --encode(encoding)--> bytes
str <--decode(encoding)-- bytes
```

**Правило:** кодировку указывайте явно; отправитель и получатель должны договориться о ней.

# `encode()` и `decode()`

```python
text = "AЯ😀"
data = text.encode("utf-8")
print(len(text), len(data))
print(data)
print(data.decode("utf-8") == text)
```

**Вывод:**

```text
3 7
b'A\xd0\xaf\xf0\x9f\x98\x80'
True
```

**Разбор:** `A` — 1 байт, `Я` — 2, `😀` — 4; всего 7.

**Гарантия языка Python 3.14.** `str.encode()` всегда даёт `bytes`, `bytes.decode()` — `str`; round-trip верен, если кодировка согласована и потерь нет.

**Граница:** `len(text)` не равен `len(data)` для не-ASCII текста.

# Unicode и UTF-8 — не синонимы

| Диапазон кодовых точек | Байтов в UTF-8 | Пример |
| --- | ---: | --- |
| `U+0000`–`U+007F` | 1 | `A` |
| `U+0080`–`U+07FF` | 2 | `Я` |
| `U+0800`–`U+FFFF` | 3 | `漢` |
| `U+10000`–`U+10FFFF` | 4 | `😀` |

Unicode задаёт кодовые точки, UTF-8 — способ представить их байтами. Таблица относится к допустимым скалярным значениям Unicode; суррогатные кодовые точки не кодируются корректным UTF-8.

```python
data = "Я".encode("utf-8")
print(data)
print(data[0], data[1])
print(data[0:1])
print("Я"[0])
```

**Вывод:**

```text
b'\xd0\xaf'
208 175
b'\xd0'
Я
```

**Разбор:** индекс `bytes` даёт число, срез — `bytes`; индекс `str` даёт строку.

# Ошибки кодирования и декодирования

```python
try:
    b"\xff".decode("utf-8")
except UnicodeDecodeError as error:
    print(type(error).__name__)
try:
    "Я".encode("ascii")
except UnicodeEncodeError as error:
    print(type(error).__name__)
print("Я".encode("ascii", errors="replace"))
print(b"\xff".decode("utf-8", errors="replace") == "\ufffd")
```

**Вывод:**

```text
UnicodeDecodeError
UnicodeEncodeError
b'?'
True
```

- `UnicodeEncodeError` — текст нельзя представить кодировкой.
- `UnicodeDecodeError` — байты не соответствуют кодировке.
- `errors="replace"` заменяет проблему, но теряет информацию; `ignore` может удалить данные молча.

**Граница:** срез байтов может разорвать многобайтовый символ UTF-8.

# Итог и повторение

**Пять правил модуля**

1. `str` — неизменяемая последовательность кодовых точек; методы возвращают новое значение.
2. Индекс берёт один элемент и может дать `IndexError`; срез берёт диапазон без правой границы и не даёт `IndexError` из-за края.
3. `len(str)` — кодовые точки, `len(bytes)` — байты; это не одно и то же.
4. `find()` даёт позицию или `-1`; `in` — `bool`; `index()` — `ValueError` при отсутствии.
5. `split()` без аргумента и с явным разделителем — разные контракты; `join()` вызывается у разделителя.

**Проверь себя вслух:** почему `s[:-1:-1]` пуст; почему `"aaaa".count("aa") == 2`; почему `str(b"ABC") != "ABC"`.

**Повторение:** через 1, 7, 14 и 30 дней; задачи — по ID из `exercises.md`, теория — по `theory.md`.
