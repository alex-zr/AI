## Как работать с банком

Задания идут по траектории «один новый приём → выбор и сочетание приёмов → перенос на непривычный случай → разбор и объяснение». Каждая задача имеет постоянный ID, подтему, категорию, сложность, точку появления, контракт, примеры и критерии проверки. Примеры — часть контракта, но не исчерпывают проверок.

**Нумерация.** ID `S02-M06-E01`–`E14` уже использованы архивной версией банка в `S02-M06_OLD/exercises.md`. По правилу проекта удалённые и заменённые ID не переиспользуются, поэтому новый банк начинается с `S02-M06-E15`.

**Соотношение с планом.** Поле `estimated_practical_tasks` из плана удалено, поэтому фиксированного числа задач по подтемам нет. Банк даёт по 6 задач на каждую из пяти подтем — это покрытие всех категорий и траектории закрепления, а не отклонение от действующего плана. Прежняя версия содержала 14 задач; расширение до 30 не меняет учебный план и теорию.

**Точки появления.** В текущем дереве `S02-M06/slides.md` и `slides_plan.md` отсутствуют. Поэтому точка появления названа по завершающему блоку подтемы и разделу теории. При сборке слайдов её нужно связать с ID последнего слайда соответствующего блока, не меняя порядок. Это зафиксированный дефицит комплекта, а не ссылка на несуществующий слайд.

**Модель сложности.** Для `str` величина `n` — число кодовых точек (code points), если не сказано иное. Для `bytes` величина `n` — число байтов. Время и дополнительная память оцениваются в учебной модели операций Python; конкретная скорость встроенных методов зависит от реализации. Дополнительная память не включает вход и возвращаемое значение, если задача не говорит иначе.

**Форма ответа.** Если задача требует вернуть строку отчёта, формат разделителей является частью контракта. Если требуется `bool`, нельзя возвращать `0`, `1` или строку. Если требуется `None`, нельзя заменять его на `-1` или `""`.

## `S02-M06-T003-P01` — Строка как последовательность

### S02-M06-E15 — Крайние знаки метки

- **Подтема и результат:** `S02-M06-T003-P01`; извлекать крайние элементы строки, считать длину и безопасно обрабатывать пустую строку.
- **Категория / сложность:** простая / 1 из 5.
- **Появление:** после блока `S02-M06-T003-P01` (теория §5.1), после примеров про `len()`, индексы и пустую строку.
- **Контекст:** панель мониторинга показывает размер короткой метки и её первый и последний элементы.
- **Условие:** напишите функцию `edge_report(text)`. Для непустой строки верните `длина|первый|последний`. Для пустой строки верните `0|-|-`. Используйте `len()` и индексацию; не пытайтесь считать видимые глифы.
- **Вход:** один объект типа `str` длиной от 0 до 100 кодовых точек.
- **Ожидаемый результат:** строка указанного формата; исходный текст не меняется.
- **Ограничения:** формат разделителей точный; для пустой строки индексация не должна выполняться.
- **Обычные случаи:** `edge_report("Кот") == "3|К|т"`; `edge_report("x") == "1|x|x"`; `edge_report("😀") == "1|😀|😀"`.
- **Граничные случаи:** `edge_report("") == "0|-|-"`; `edge_report("e\u0301") == "2|e|\u0301"` — комбинируемый акут является отдельной кодовой точкой.
- **Критерии проверки:** длина и оба индекса верны; пустая строка не вызывает `IndexError`; формат совпадает посимвольно; результат не зависит от числа видимых знаков.
- **Сложность:** время `O(1)` в учебной модели доступа к длине и индексу; дополнительная память `O(1)` без учёта возвращаемой строки.

### S02-M06-E16 — Паспорт кодовой точки

- **Подтема и результат:** `S02-M06-T003-P01`; различать строку длины 1 и последовательность из нескольких кодовых точек, применять `ord()`.
- **Категория / сложность:** простая / 2 из 5.
- **Появление:** после блока `S02-M06-T003-P01` (теория §5.1), после примеров с `ord()` и `chr()`.
- **Контекст:** отладчик текстового редактора показывает кодовую точку выделенного элемента.
- **Условие:** напишите функцию `codepoint_label(ch)`. Если `ch` — строка ровно из одной кодовой точки, верните `сам_символ=0xкод`, где код получен через `hex(ord(ch))`. Иначе верните `invalid`.
- **Вход:** один объект типа `str` длиной от 0 до 3 кодовых точек.
- **Ожидаемый результат:** строка отчёта либо `invalid`.
- **Ограничения:** используйте `len()` и `ord()`; не считайте, что один видимый знак всегда имеет длину 1.
- **Обычные случаи:** `codepoint_label("A") == "A=0x41"`; `codepoint_label("я") == "я=0x44f"`; `codepoint_label("😀") == "😀=0x1f600"`.
- **Граничные случаи:** `codepoint_label("") == "invalid"`; `codepoint_label("ab") == "invalid"`; `codepoint_label("\u0301") == "\u0301=0x301"`.
- **Критерии проверки:** длина проверяется до `ord()`; для одной кодовой точки формат точный; `ord()` не вызывается для строки недопустимой длины.
- **Сложность:** время `O(1)`; дополнительная память `O(1)` без учёта результата.

### S02-M06-E17 — Палиндром без разворота

- **Подтема и результат:** `S02-M06-T003-P01`; прослеживать два индекса от разных концов и объяснять границы цикла.
- **Категория / сложность:** средняя / 3 из 5.
- **Появление:** после блока `S02-M06-T003-P01` (теория §5.1) и после задачи `E15`.

- **Условие:** напишите функцию `is_palindrome(text)`, которая возвращает `True`, если строка читается одинаково слева направо и справа налево, и `False` иначе. Сравнение чувствительно к регистру; пробелы и знаки пунктуации не удаляются. Реализуйте проверку двумя индексами без `text[::-1]`.

- **Критерии проверки:** возвращается именно `bool`; пустая и одноэлементная строки истинны; регистр учитывается; индексы не выходят за границы.

### S02-M06-E18 — Безопасная ячейка по индексу

- **Подтема и результат:** `S02-M06-T003-P01`; проверять допустимость положительного и отрицательного индекса до обращения.
- **Категория / сложность:** средняя / 2 из 5.
- **Появление:** после блока `S02-M06-T003-P01` (теория §5.1), после примеров с `IndexError`.
- **Контекст:** API отчёта принимает индекс ячейки, но не должен падать на неверном запросе.
- **Условие:** напишите функцию `char_at(text, index)`. Если индекс допустим, верните `ok:<элемент>`. Если нет — `missing`. Поддерживайте отрицательные индексы по обычным правилам Python. Не используйте `try`/`except`.
- **Вход:** `text` — `str`, `index` — целое число.
- **Ожидаемый результат:** `"ok:"` плюс один элемент строки либо `"missing"`.
- **Ограничения:** проверка должна работать для пустой строки и для индексов далеко за границами.
- **Обычные случаи:** `char_at("Кот", 0) == "ok:К"`; `char_at("Кот", -1) == "ok:т"`; `char_at("Кот", 2) == "ok:т"`.
- **Граничные случаи:** `char_at("Кот", -3) == "ok:К"`; `char_at("Кот", 3) == "missing"`; `char_at("Кот", -4) == "missing"`; `char_at("", 0) == "missing"`.
- **Критерии проверки:** отрицательный индекс не считается заведомо ошибочным; границы `-len(text)` и `len(text) - 1` включены; за ними возвращается `missing`; исключение не возникает.
- **Сложность:** время `O(1)`; дополнительная память `O(1)` без учёта результата.

### S02-M06-E19 — Сдвиг латинских букв

- **Подтема и результат:** `S02-M06-T003-P01`; переносить знание о кодовых точках на посимвольное преобразование с закольцованным диапазоном.
- **Категория / сложность:** сложная / 4 из 5.
- **Появление:** после блока `S02-M06-T003-P01` (теория §5.1), после задач `E16`–`E18`.
- **Контекст:** учебный шифр сдвигает только заглавные латинские буквы, не трогая остальные знаки.
- **Условие:** напишите функцию `shift_letters(text, shift)`. Каждую букву `A`–`Z` замените буквой, сдвинутой на `shift` позиций по кругу; строчные буквы, цифры, пробелы, кириллица, эмодзи и пунктуация остаются без изменений. `shift` может быть любым целым, включая отрицательное и большое.
- **Вход:** `text` — `str`; `shift` — целое число.
- **Ожидаемый результат:** новая строка той же длины в кодовых точках.
- **Ограничения:** не используйте таблицы замены в виде `dict` и не перечисляйте 26 пар вручную; применяйте `ord()`/`chr()` и арифметику по модулю.
- **Обычные случаи:** `shift_letters("ABC", 1) == "BCD"`; `shift_letters("XYZ", 3) == "ABC"`; `shift_letters("Hello, World!", -1) == "Gello, Vorld!"`.
- **Граничные случаи:** `shift_letters("AZ", 26) == "AZ"`; `shift_letters("AZ", -27) == "ZY"`; `shift_letters("Кот", 5) == "Кот"`; `shift_letters("", 7) == ""`.
- **Критерии проверки:** сдвиг нормализуется по модулю 26; границы алфавита закольцованы; нелатинские знаки не меняются; длина результата равна длине входа; отрицательный сдвиг работает.
- **Сложность:** время `O(n)`; дополнительная память `O(n)` на результат (без учёта результата — `O(1)`).

### S02-M06-E20 — Разбор и исправление: последний элемент

- **Подтема и результат:** `S02-M06-T003-P01`; находить ошибку на единицу в индексации и объяснять разницу между недопустимым индексом и безопасным обращением.
- **Категория / сложность:** интервью / 2 из 5.
- **Появление:** после блока `S02-M06-T003-P01` (теория §5.1) и задач `E15`–`E19`.
- **Контекст:** на code review коллега утверждает, что функция возвращает последний символ, но на пустом вводе падает.
- **Условие:** дан код:

  ```python
  def last_char(text):
      return text[len(text)]
  ```

  Исправьте функцию так, чтобы она возвращала последний элемент непустой строки и `""` для пустой. Объясните: (1) почему исходное выражение неверно; (2) почему `text[-1]` нельзя использовать без проверки; (3) что вернёт исправленная функция для `"e\u0301"`.
- **Вход:** один объект типа `str`.
- **Ожидаемый результат:** исправленная функция и письменное объяснение.
- **Ограничения:** нельзя менять имя функции; нельзя использовать `try`/`except`; объяснение должно отличать длину от последнего индекса.
- **Обычные случаи:** `last_char("Кот") == "т"`; `last_char("a") == "a"`.
- **Граничные случаи:** `last_char("") == ""`; `last_char("e\u0301") == "\u0301"`.
- **Критерии проверки:** исправленная функция проходит все примеры; объяснение называет `len(text)` как первый недопустимый индекс; проверка пустой строки стоит до `text[-1]`; комбинируемый знак трактуется как отдельная кодовая точка, а не как «один видимый символ».
- **Ожидаемые уточнения:** считается ли «символ» кодовой точкой или графемным кластером; что делать с пустой строкой — возвращать `""`, `None` или ошибку; допустимо ли менять контракт функции.
- **Критерии устного объяснения:** коротко назвать правило `последний индекс = len(text) - 1`; показать, что при `len(text) == 0` допустимых индексов нет; отделить `IndexError` от `TypeError` при попытке изменить строку; не утверждать, что `text[-1]` всегда безопасен.
- **Сложность:** время `O(1)`; дополнительная память `O(1)`.

### S02-M06-E23 — Циклический сдвиг строки

- **Подтема и результат:** `S02-M06-T003-P02`; сочетать срезы с арифметикой по модулю и обрабатывать пустую строку.

- **Появление:** после блока `S02-M06-T003-P02` (теория §5.2), после задач `E21`–`E22`.
- **Контекст:** карусель подсказок циклически сдвигает короткий текст влево на `k` позиций.

- **Условие:** напишите функцию `ascii_safe(text)`, которая кодирует текст в ASCII с политикой `errors="replace"` и декодирует обратно. Если результат совпадает с исходным текстом, верните `same:<результат>`; иначе `lost:<результат>`.
- **Вход:** один объект типа `str`.
- **Ожидаемый результат:** строка отчёта.
- **Ограничения:** используйте явную кодировку `"ascii"`; не удаляйте символы через `ignore`; не сравнивайте байты с текстом напрямую.
- **Обычные случаи:** `ascii_safe("ABC") == "same:ABC"`; `ascii_safe("AЯ") == "lost:A?"`; `ascii_safe("😀") == "lost:?"`.
- **Граничные случаи:** `ascii_safe("") == "same:"`; `ascii_safe("?") == "same:?"`; `ascii_safe("A B") == "same:A B"`.
- **Критерии проверки:** потеря обнаруживается сравнением текста, а не длины; `?` в исходной строке не считается потерей; пустой вход даёт `same`; политика `replace` использована явно.
- **Сложность:** время `O(n)`; дополнительная память `O(n)`.

### S02-M06-E43 — Проверка ASCII-протокола по байтам

- **Подтема и результат:** `S02-M06-T004-P03`; переносить знание о `bytes` как последовательности целых на проверку протокола.
- **Категория / сложность:** сложная / 4 из 5.
- **Появление:** после блока `S02-M06-T004-P03` (теория §5.5), после задач `E39`–`E42`.
- **Контекст:** сетевое поле обязано содержать только ASCII; при нарушении нужно вернуть позицию и значение проблемного байта.
- **Условие:** напишите функцию `ascii_guard(data)`. Проверьте байты по одному. Если все значения не больше `127`, верните `ok:` и декодированный вручную текст (соберите его через `chr()`). Иначе верните `bad:<индекс>:<значение>` для первого нарушения. Для пустого входа верните `ok:`.
- **Вход:** объект `bytes` длиной от 0 до 10 000.
- **Ожидаемый результат:** строка отчёта.
- **Ограничения:** не используйте `bytes.decode()` и `str(data)`; не считайте, что `data[0]` — строка; проверка идёт слева направо до первого нарушения.
- **Обычные случаи:** `ascii_guard(b"ABC") == "ok:ABC"`; `ascii_guard(b"A\xffB") == "bad:1:255"`.
- **Граничные случаи:** `ascii_guard(b"") == "ok:"`; `ascii_guard(b"\x80") == "bad:0:128"`; `ascii_guard(b"\x7f") == "ok:\x7f"`; `ascii_guard(b"\xd0\xaf") == "bad:0:208"` — это первые байты UTF-8 для `Я`, но для ASCII они недопустимы.
- **Критерии проверки:** граница `127` включена; значение `128` уже ошибка; возвращается первый проблемный индекс; текст собирается из чисел через `chr()`; пустой вход корректен; `decode()` не использован.
- **Сложность:** время `O(n)`; дополнительная память `O(n)` на результат.

### S02-M06-E44 — Бюджет сообщения в байтах

- **Подтема и результат:** `S02-M06-T004-P03`; переносить правило «символ UTF-8 занимает переменное число байтов» на ограничение сообщения без разрыва кодовой точки.
- **Интеграция:** использует `S02-M06-T003-P01` (`len()`), `S02-M06-T003-P02` (срез) и `S02-M06-T004-P03`; учитывается в `T004-P03`.
- **Категория / сложность:** интервью / 4 из 5.
- **Появление:** после блока `S02-M06-T004-P03` (теория §5.5), после задачи `E43`.
- **Контекст:** SMS-шлюз принимает сообщение, у которого UTF-8 представление не больше `limit` байтов; обрезать символ посередине нельзя.
- **Условие:** напишите функцию `fit_message(text, limit)`, возвращающую самый длинный префикс из целых кодовых точек, чьё UTF-8 представление не превышает `limit` байтов, в формате `префикс|кодовых_точек|байтов`. Если не помещается даже первый символ, верните `|0|0`. `limit` неотрицателен. Многоточие не добавляйте.
- **Вход:** `text` — `str`; `limit` — целое число `>= 0`.
- **Ожидаемый результат:** строка отчёта.
- **Ограничения:** не срезайте `bytes` по `limit` — это может разорвать UTF-8; не добавляйте символы, которых не было; кодировка `"utf-8"` явная.
- **Обычные случаи:** `fit_message("AЯ😀", 7) == "AЯ😀|3|7"`; `fit_message("AЯ😀", 5) == "AЯ|2|3"`; `fit_message("AЯ😀", 2) == "A|1|1"`.
- **Граничные случаи:** `fit_message("AЯ😀", 4) == "AЯ|2|3"`; `fit_message("AЯ😀", 1) == "A|1|1"`; `fit_message("AЯ😀", 0) == "|0|0"`; `fit_message("😀", 3) == "|0|0"`; `fit_message("😀", 4) == "😀|1|4"`; `fit_message("", 10) == "|0|0"`.
- **Критерии проверки:** префикс состоит из целых кодовых точек; фактическая длина UTF-8 не больше `limit`; добавление следующей кодовой точки нарушило бы лимит; число кодовых точек и байтов в отчёте верны; пустой вход и слишком маленький лимит дают `|0|0`.
- **Ожидаемые уточнения:** `limit` задан в байтах или в кодовых точках; входит ли многоточие в лимит; что делать, если первый символ не помещается — пустая строка или ошибка; можно ли менять текст, например заменять эмодзи; считается ли BOM частью сообщения.
- **Критерии устного объяснения:** объяснить, что UTF-8 имеет переменную длину и `len(str) != len(bytes)`; показать, почему срез `encoded[:limit]` может дать `UnicodeDecodeError`; предложить посимвольный подсчёт с накоплением и ранним выходом; обосновать сложность `O(n)` по числу проверенных кодовых точек и память `O(k)` на префикс; отделить контракт «не добавлять многоточие» от возможной политики вызывающего кода.
- **Сложность:** время `O(n)`; дополнительная память `O(k)`, где `k` — число кодовых точек в префиксе, без учёта результата.
